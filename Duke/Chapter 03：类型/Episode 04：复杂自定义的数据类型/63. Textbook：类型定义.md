# Typedef（类型定义）

![[Pasted image 20260917125627.png]]
许多人认为上图中的**选项 1** 有些笨拙，因为变量的类型中包含单词 `struct`。例如，假设你想要一个名为 `shrinkRect` 的函数，它接受一个矩形作为输入，并返回一个更小的矩形作为输出。使用选项 1 的语法，该函数将具有如下签名：

```c
struct rect_t shrinkRect(struct rect_t shrinkThisRectangle);
```

根据你需要写出结构体类型的频率，这种语法可能变得**笨重**，并使代码显得**杂乱**。

每次声明、传递或使用新结构体时都需要写出 `struct rect_t`，解决这个问题的办法是：**创建一个显式类型为 struct 的新数据类型**。我们使用关键字 `typedef` 来做到这一点。确切的语法如上图**选项 2** 所示。最开始几行像之前一样声明 `rect_tag` 结构体。然而，在这个结构体定义之后，最后一行：

```c
typedef struct rect_tag rect_t;
```

是类型 `rect_t` 的声明，它被定义为具有类型 `struct rect_tag`。使用 `_tag` 使代码更易读，并鼓励使用类型名而不是标签名。选项 3 和 4 也“typedef”一个新类型，不过它们都把 `typedef` 合并到与结构体声明相同的单条语句中。

尽管 `typedef` 可以简化结构体的使用，但这远不是它唯一的用途。**任何时候你在特定上下文中编写代码，`typedef` 都可以通过根据类型的含义和用途来命名类型，帮助你使代码更具可读性**。例如，假设你正在编写一个处理颜色的程序。

在编程颜色特征的上下文中，你可能想为 RGB 值中的颜色定义一个新的数据类型。例如，你可以创建一个名为 `rgb_t` 的新数据类型（它表示颜色的红色、绿色或蓝色分量之一），其类型为 `unsigned int`（无符号整数类型）（因为我们知道这些值应该是正整数），然后声明类型为 `rgb_t` 的变量 `red`、`green` 和 `blue`。其示例显示在下图的左侧。
![[Pasted image 20260917125710.png]]

`typedef` 为程序员提供了有用的**抽象**。程序员无需在整个代码中编写 `unsigned int`，或者坦率地说，甚至无需考虑 RGB 表示中可接受值的范围，只需使用自定义类型 `rgb_t`，而无需进一步思考。

`typedef` 还有另一个很好的特性：**将特定类型的定义限制在代码库中的单个位置**。假设程序员希望节省专用于变量的空间，因此希望使用 `unsigned char`（无符号字符类型）而不是 `unsigned int`（无符号整数类型）（毕竟，从 0 到 255 的值都适合 `unsigned char` 的 8 位）。如果没有 `typedef`，这种更改将需要在代码中许多（但绝非全部——它可能用于与颜色无关的变量）`unsigned int` 实例中进行繁琐且容易出错的搜索，并将这些类型更改为 `unsigned char`。有了 `typedef`，程序员只需更改定义 `rgb_t` 的那一行代码（见图右侧）。不需要其他代码更改。

**关于 `typedef` 的提醒**：在某些编程圈子里，`typedef` 的使用有些**争议**。在结构体的上下文中，有些人认为重要的是不要将结构体从类型中抽象出来。他们认为程序员应该始终知道特定变量何时是结构体，何时不是。同样，他们认为程序员应该始终了解自己使用的数据的实际类型，以免陷入本来可以避免的类型错误。**当抽象能简化而不是混淆你的代码时，才使用 `typedef`**。
