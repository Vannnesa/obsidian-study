有时，程序员希望**显式请求**从一种类型到另一种类型的转换——要么因为编译器没有理由自动插入转换（类型已经相同，但希望进行不同类型的运算），要么因为编译器认为该转换不够“安全”，不能自动执行。这种显式请求的转换称为**强制类型转换**（casting），在代码中通过将目标类型放在括号中、置于需要转换值的表达式之前来书写。例如，`(double)x` 会先求值 `x`（读取其“盒子”中的值），然后将其转换为 `double`（双精度浮点类型）。

为了理解为什么需要这种能力，我们先看一个看似无害的例子。我们想编写一个程序，计算如果把每周 40 小时的工作量分摊到 7 天而不是 5 天，那么你每天需要工作多少小时。一个朴素的代码实现可能首先定义两个 `int`（整数类型）：`nHours` 和 `nDays`。

```c
int main(void) {
  int nHrs = 40;
  int nDays = 7;
  
  float avg = nHrs/nDays;
  printf("%d hours in %d days\n", nHrs, nDays);
  printf("work %.1f hours per day!\n", avg);
  //...
}
```

这里，`int` 是完全合理的类型，因为我们只处理整数小时数（40）和天数（5）。然后这段代码将小时数除以天数，并把结果存储到 `float`（浮点类型）的 `avgWorkDay` 中。如果你仔细手工执行这段代码，会发现它打印答案时会输出 `5.0`。不知怎么的，我们的工作周一下子缩短到了 35 小时！

在这种情况下，问题在于我们除以了两个 `int`，而**整数除法总是产生整数结果**——这里是 `5`。当编译器查看这个表达式时，其中只涉及整数，因此它认为没有必要把任何一个操作数转换为其他类型。于是它生成指令，请求 CPU 执行整数除法，产生整数结果。

然而，当编译器检查赋值时，它看到左侧的类型（用于存储值的“盒子”的类型）是 `float`，而右侧表达式的类型（除法结果值的类型）是 `int`。然后它会在赋值处插入类型转换指令：在把整数除法结果放入“盒子”时，将其转换为浮点数。

这里，我们真正想要做的是在除法发生之前，将两个操作数都转换为实数类型（`float` 或 `double`），然后对实数执行除法。我们可以通过引入**显式强制类型转换**（explicit cast）——请求类型转换——来实现这个目标。

```c
int main(void) {
  int nHrs = 40;
  int nDays = 7;
  
  float avg = nHrs/(float)nDays;
  printf("%d hours in %d days\n", nHrs, nDays);
  printf("work %.1f hours per day!\n", avg);
  //...
}
```

我们可以显式转换两个操作数，不过，**转换其中任何一个就足以实现目标**。一旦一个操作数被转换为实数类型，编译器就被迫自动转换另一个。我们更倾向于写 `a / (double) b`，而不是 `(double) a / b`，尽管它们等价，因为前者不要求代码读者记住强制类型转换和数学运算符之间的相对优先级（“运算顺序”）。不过，我们注意到，**强制类型转换具有非常高的运算符优先级**——它在运算顺序中发生得相当早。这个例子在下面的视频中展示。
