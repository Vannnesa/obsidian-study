# Overflow and Underflow（溢出与下溢）

下图展示了 C 中支持的一些基本类型及其大小。
![[Pasted image 20260917112305.png]]

每种类型都有**固定大小**，这会对某个特定类型的变量所能存储的**最小值和最大值**造成限制。例如，`short`（短整型）通常是 16 位，这意味着它正好能表示 `2^16` 个可能值。如果这些值被分配给正数和负数，那么 `short` 中能存储的最大正数就是 `0111111111111111`，即 `32767`。

如果你尝试给这个数加 1，会发生什么？加 1 会得到并不令人意外的 `1000000000000000`。这个位模式符合预期。但是，当把该位模式解释为 `signed short`（有符号短整型）时，它的值是 `-32768`，这可能令人惊讶（非常流行的 xkcd 漫画很好地说明了这个原理：  
http://xkcd.com/571/ ）。如果 `short` 是 `unsigned`（无符号）的，那么同样的位模式 `1000000000000000` 会被解释为并不令人意外的 `32768`。

这种奇怪的行为就是**溢出**（overflow）的一个例子：一个运算得到的结果数**太大**，以至于无法由该运算的**结果类型**表示。相反的效果称为**下溢**（underflow）：一个运算得到的结果数**太小**，以至于无法由该运算的结果类型表示。溢出是类型大小限制的**自然结果**。

注意，溢出（以及下溢）是**在特定运算期间发生的行为**。正确的说法是：“执行 16 位有符号加法 `32767 + 1` 会导致溢出。”不正确的说法是：“`-32768` 溢出了。” `-32768` 这个数本身完全没问题。溢出（或下溢）问题发生在你用 `32767 + 1` 得到 `-32768` 的时候。运算不一定非得是“数学”运算才会表现出溢出。**将较大类型赋值给较小类型**也可能导致溢出。考虑以下代码：

```c
short int s;
int x = 99999;
s = x;
printf("%d\n", s);
```

在这段代码中，将 `x`（32 位 `int`）赋值给 `s`（16 位 `short int`）会溢出——类型转换中执行的**截断**会丢弃非零位。这段代码将打印出 `-31073`，对于不理解溢出的人来说，这会相当意外。

溢出是否会影响程序的正确性，**取决于具体上下文**。例如，时钟每天会经历两次溢出，却没有问题。（`12:59` 后面是 `1:00` 是预期行为。）作为程序员，要认识到：你对类型的选择决定了每个变量的上下限，并且你有责任了解每种选择下溢出的可能性和影响。
