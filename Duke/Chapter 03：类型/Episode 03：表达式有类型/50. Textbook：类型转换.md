
下一个自然问题是："如果有一个二进制运算符，而其操作数具有不同的类型，会发生什么情况？例如，如果 a 是 int，b 是 double，那么 a + b 是什么类型？这个问题的答案取决于所涉及的类型。

从根本上说，首先必须将两个操作数转换为相同的类型。大多数运算只能在相同类型的操作数上进行。处理器有一条指令可以将两个 32 位整数相加，另一条指令可以将两个 16 位整数相加，第三条指令可以将两个 32 位浮点数相加，第四条指令可以将两个 64 位双倍数相加，等等。编译器必须将你的代码翻译成这些指令中的一条，因此，它必须选择其中一条指令，并以适当的格式安排输入，以便能够执行数学运算。

当两个操作数的类型不同时，编译器会尝试增加一个_类型转换_（有时称为_类型提升_），使其类型相同。如果无法进行类型转换，编译器会发出错误信息并拒绝编译代码。当编译器插入类型转换时，通常必须在程序中添加指令，使处理器显式地改变位表示，从原始类型使用的大小和表示方式改为新类型使用的大小和表示方式。编译器会根据 "最佳 "答案来选择要转换的操作数。在我们的 int + double 例子中，编译器会将 int 转换为 double，以避免丢失数字的小数部分。

在类型晋升过程中，有四种常见的方式必须改变位表示，以便从一种类型转换到另一种类型。从较小的有符号整数类型转换为较长的有符号整数类型时，必须对数字进行符号扩展--必须复制适当次数的符号位（最显著位）以填充额外的位。当从较小的无符号整数类型转换为较长的无符号整数类型时，必须对数字进行零扩展--用所有零填充附加位。在自动转换过程中，改变位表示的第三种常见方式是将较长的整数类型转换为较短的整数类型。在这种情况下，比特模式会被截断以适应--最重要的比特被丢弃，只保留最不重要的比特。

第四种可能需要更改位表示的方式是，完全计算新类型中值的表示。例如，当从整数类型转换为实数类型时，编译器必须插入一条指令，要求 CPU 计算该整数的浮点（二进制科学符号）表示法。

## '强制' 类型转换
在其他情况下，类型转换无需改变位模式，而只需改变解释方式。例如，将**有符号 int** 转换为**无符号 int** 时，位模式保持不变。但是，如果数值原来是负数，现在就会被解释为大正数。请看下面的代码：
````c
unsigned int bigNum = 100; 
int littleNum = -100;
if (bigNum > littleNum) {
  printf("Obviously, 100 is bigger than -100!\n"); 
}
else {
  printf("Something unexpected has happened!\n");
}
````
当这段代码运行时，它会打印出“发生了意料之外的事情！”。`littleNum` 的位模式（因为它为负数，所以有一个前导 1）被保留了下来；但它的值被变成了一个大于 100 的数（因为在无符号解释下，这个前导 1 表示一个非常大的数）。我们要注意，对于这种行为，编译器会产生一个警告（这是一个提示，说明你可能做了坏事——也就是说，你应该去修正你的代码！），因为将有符号整数与无符号整数进行比较，正是出于这个原因，通常是个坏主意。

当你声明一个变量并赋予它某个特定类型时，你就指定了你希望与该变量关联的数据——也就是“盒子中”的位模式——在其整个生命周期中如何被解释。然而，有些时候，你或编译器可能不得不临时将该变量当作另一种类型来处理。当程序员这样做时，称为强制类型转换；当编译器这样做时，称为类型转换或类型提升。理解前者何时该做、以及编译器何时在做后者，极其重要，因为它常常会造成困惑，并因此导致错误。我们要注意，虽然理解何时该进行强制类型转换很重要，但理解你通常不应该进行强制类型转换更重要——为了让错误消失而在代码中到处添加***强制类型转换***，表明你并没有真正修复代码，而只是把其中的问题隐藏起来。
