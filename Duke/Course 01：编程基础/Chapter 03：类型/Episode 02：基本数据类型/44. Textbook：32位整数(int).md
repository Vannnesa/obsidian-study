我们说过，int 是直接从二进制表示法解释为整数的 32 位数值。事实证明，这只是故事的一半--正数的一半。如果我们将所有 32 位都用于表达正数，那么我们就可以表达从 0 到 4,294,967,295 的 2^{32} 个数值。如下图第二行所示，我们在声明中使用限定符 unsigned 来要求这种解释。

实际上，ints 使用的是一种称为 "二进制 "的编码方式，在这种编码方式中，2^{32} 种可能的位模式中，一半用于表示负数，另一半用于表示正数。具体来说，所有最有效位等于 1 的数字都是负数。32 位 int 本身就是带符号的（即既能表示正值，也能表示负值），可以表示 -2,147,483,648 到 2,147,483,647 之间的数值。请注意，无符号 int 和有符号 int 都有 2^{32} 个可能值。对于无符号 int，它们都是正值；对于有符号 int，一半是正值，一半是负值。

在二进制补码中，对一个数字进行负运算的过程可能看起来有点奇怪，但当你明白为什么要这样设置时，就会发现其实很有道理。 要计算负数 X，需要将 X 的位数翻转（将 0 变为 1，将 1 变为 0），然后加 1。因此，如果使用 4 位二进制，取数字 5 (0101)，并希望得到负数 5，则首先要翻转位数 (1010)，然后加 1 (1011)。 为什么计算机科学家会选择这样一个奇怪的规则呢？ 原来，这条规则让你可以自然地进行数字相加，无论数字是正数还是负数，都能得到正确的结果。 例如，-5 + 1 = -4，而二进制 1011 + 0001 是 1100。 要知道 1100 是-4，只需翻转位 (0011) 并加上 1 (0100) 即可得到 4。

你可能会遇到的另一对限定符是 short 和 long，它们可以分别减少或增加特定变量的总位数。例如，short int（在 C 语言中也简称为 short）通常只有 16 位长。从技术上讲，C 语言标准的唯一要求是短 int 的位数少于或等于 int 的位数，而长 int 的位数大于或等于 int 的位数。
