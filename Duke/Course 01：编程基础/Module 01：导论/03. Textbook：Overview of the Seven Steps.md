This figure shows a high-level overview of the programming process. A programmer starts by devising the algorithm for the task she is trying to solve. We will split this planning phase into four steps in the process of writing a program, which we will discuss in more detail shortly. At the end of these four steps, the programmer should have a complete plan for the task at hand—and be convinced that the plan is a good one. After devising a proper algorithm, she is ready for Step 5 of the programming process: translating her plan into code in the programming language she is using for her current project. Initially, translation to code will go slowly, as you will be unfamiliar with the syntax, likely needing to look up the specific details often. However, even if slow, it should be fairly straightforward. You already devised the plan, so you should have done all the actual problem-solving tasks already. Your algorithm may have some complex steps, but that is fine. As we will see later, whenever your algorithm calls for a step that is too complicated to be simply translated into a few lines of code, you should turn that step into its own separate programming task and repeat the programming process on it. In the next course, we will discuss translation to code in much more detail, as well as how to turn the code into something that the computer can run. Once the algorithm is implemented in code, the programmer must test her code, which is the 6th Step of the programming process. By testing the program, the programmer tries to uncover errors in her algorithm or implementation. If the programmer finds errors in her program, she debugs the program (Step 7): finding out the cause of the error, and fixing it. The programmer may need to return to the algorithm design steps (if the error lies in the algorithm) or to translation to code (if the error lies in the implementation) to correct the error. The programmer then repeats all of the later steps. 2/2 At some point, the programmer completes enough test cases with no errors to become convinced that her program is correct. Note that we said the programmer becomes convinced that her program is correct. No amount of testing can guarantee that the program is correct. Instead, more testing increases the programmer's confidence that the code is correct. When the programmer is convinced her code is correct, she has successfully completed the task at hand. We will discuss testing and debugging in much more detail in the next course.

设计出合适的算法后，程序员就可以开始编程过程的第五步：用当前项目使用的编程语言将计划转化为代码。起初，由于不熟悉语法，可能需要经常查找具体细节，因此转化为代码的过程会比较缓慢。不过，即使缓慢，也应该相当简单。你已经制定了计划，所以你应该已经完成了所有实际解决问题的任务。你的算法可能会有一些复杂的步骤，但这没有问题。正如我们稍后将看到的，每当你的算法要求的步骤过于复杂，无法简单地转化为几行代码时，你就应该将该步骤转化为自己独立的编程任务，并对其重复编程过程。在下一门课程中，我们将更详细地讨论将算法转化为代码，以及如何将代码转化为计算机可以运行的内容。

在代码中实现算法后，程序员必须测试其代码，这是编程过程的第六步。通过测试程序，程序员试图发现算法或实现过程中的错误。如果程序员发现了程序中的错误，就会对程序进行调试（第 7 步）：找出错误的原因并加以修正。程序员可能需要回到算法设计步骤（如果错误出在算法上）或翻译成代码（如果错误出在实现上）来纠正错误。然后，程序员会重复后面的所有步骤。

到了某个阶段，程序员完成了足够多的测试用例，没有出现任何错误，从而确信自己的程序是正确的。请注意，我们说的是程序员_确信_其程序是正确的。再多的测试也不能保证程序是正确的。相反，更多的测试会增加程序员对代码正确性的信心。当程序员确信自己的代码是正确的时候，她就成功完成了手头的任务。我们将在下一门课程中更详细地讨论测试和调试。
