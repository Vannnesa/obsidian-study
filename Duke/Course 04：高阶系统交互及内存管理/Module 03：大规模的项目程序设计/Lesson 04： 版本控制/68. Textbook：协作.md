# Collaboration
# 协作

当你参与一个拥有数百个源文件和几十名开发者的软件项目时，如何让每个人都了解最新的源代码？来回通过电子邮件发送文件会是一场噩梦。即使只有两个人参与一个项目，管理开发者之间的变更也是**首要问题**。

像 Git 这样的版本控制系统支持**推送**（pushing）——把你的更改发送到另一个仓库（位于另一台计算机上）——和**拉取**（pulling）更改——从另一个仓库获取最新版本。如果你尝试推送自己的更改，但没有与另一个仓库保持同步，Git 会要求你先拉取，这样你就**不会意外覆盖别人的更改**。当你拉取时，Git 会小心确保你的更改与远程更改集成。

如果你拉取，并且（自上次推送到该仓库以来）没有对自己的仓库做任何更改，Git 会简单地把你的仓库更新到最新版本。如果你做了更改，Git 会尝试把你的更改与远程更改**合并**（merge）。如果你更改了不同的文件，或同一文件的不同部分，Git 通常会**自动处理合并**。然而，如果 Git 无法自动合并，它会指出需要你注意的问题，并要求你在把更改推回去之前修复它们。
