# Planning the High-Level Algorithm
# 规划高层算法

一如既往，我们应该从**步骤 1** 开始，并贯穿我们在本书中学到的整个编程过程。当然，对于这么大的任务，我们应该认识到，我们是要把任务分解成许多函数，因此我们应该满足于相对复杂的步骤——这些步骤随后决定了我们需要哪些函数。

我们可以朝着解决这个问题迈出几个重要步骤。第一个是我们可以定义问题中涉及的几个类型。视频中讲解了如何得出我们的 `student_t` 和 `roster_t` 类型。我们同样可以推导出表示所有课程列表所需的 `classes_t` 类型。然后我们会得出以下声明：

记住这些类型声明，在我们处理即将创建的子问题时会很有帮助。这些类型将成为许多其他算法的输入和/或输出类型。确切知道它们长什么样，使我们能够在步骤 1 中为每个问题画出精确的图，从而得出正确的算法。

我们在视频中采取的另一个重要步骤是得出 `main` 的总体算法：

```text
从 argv[1] 指定的文件中读取输入（称之为 r）
创建所有（唯一）课程名称的列表（称之为 c）
为每个课程写一个输出文件（从 c 和 r）
```

我们将对这个算法做一些修改。首先，我们会注意到我们没有写下任何关于返回答案的内容——然而，`main` 总是返回一个 `int`。在这种情况下，我们应该返回 `EXIT_SUCCESS`。当我们仔细思考其他函数（我们即将编写的）会做什么时，我们可能会意识到它们需要 `malloc` 一些内存——所以我们应该在用完时释放那块内存。如果我们还没有意识到这一点，我们可能需要稍后回来添加释放。此外，如果我们在步骤 4 中仔细测试（用边界情况），我们可能会意识到需要添加一些错误检查。最终，这导致一个很好的泛化后的 `main` 算法：

```text
检查 argc == 2（如果不是则失败）
从 argv[1] 指定的文件中读取输入（称之为 the_roster）
检查 r != NULL（如果不是则失败）
创建所有课程名称的列表（称之为 unique_class_list）
从 unique_class_list 和 the_roster 写出所有课程名册文件
释放 unique_class_list 持有的内存
释放 the_roster 持有的内存
返回 EXIT_SUCCESS
```

只要我们每个复杂的步骤都抽象到它自己的函数中，这就会产生一个很好的、简短的、易于理解的 `main` 函数：

```c
int main (int argc, char ** argv) {
  if (argc != 2) {
    fprintf(stderr, "Usage: roster inputname\n");
    return EXIT_FAILURE;
  }
  roster_t * the_roster = readInput (argv[1]);
  if (the_roster == NULL) {
    fprintf(stderr,"Could not read the roster information\n");
    return EXIT_FAILURE;
  }
```

写好了 `main` 之后，我们现在有了五个新的编程任务，每个都将是一个函数：`readInput`、`getClassList`、`writeAllFiles`、`freeClasses` 和 `freeRoster`。
