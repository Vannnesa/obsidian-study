这段代码把编写一个文件的任务抽象到它自己的函数中，让 `writeAllFiles` 只需遍历课程列表，并让 `writeOneFile` 做主要工作。`writeOneFile` 函数抽象出了 `makeRosterFileName`，因为那本身是把泛化算法翻译成代码时一个有点复杂的步骤。然后我们可以编写这个函数：

```c
char * makeRosterFileName(const char * cName) {
  const char * suffix = ".roster.txt";
  unsigned len = strlen(cName) + strlen(suffix) + 1;
  char * ans = malloc(len * sizeof(*ans));
  snprintf(ans, len, "%s%s", cName, suffix);
  return ans;
}
```

此时，我们就完成了编程任务。我们编写了 **14 个函数**，但每个函数大小都合理（全部少于 25 行），并且有明确定义的目的。注意这种抽象如何有助于代码的**可读性**。你可以查看一个函数，它足够小，你可以思考它做什么。然后你可以根据高层函数所调用的低层函数来理解它们——知道它们做什么，而不必在那时担心它们如何做。这就是良好抽象的**好处**。

此外，我们的代码**易于修改**。例如，假设我们决定更改输入文件的格式，使每个学生的条目不再以他们拥有的课程数量开始；相反，他们的条目以空行结束。我们只需要修改 `readAStudent`，因为那段代码是唯一处理读取学生信息的部分。其他所有内容都通过把该任务抽象到 `readAStudent` 函数中，而与如何读取学生的细节隔离开来。其余代码（特别是 `readInput`）只需要知道 `readAStudent` 会读取一个学生条目并返回指向它的指针。如果我们对输入格式做更剧烈的更改，那么对代码更改的影响将仅限于 `readInput` 及其调用的函数。其他任何东西都不关心如何读取输入的细节。
