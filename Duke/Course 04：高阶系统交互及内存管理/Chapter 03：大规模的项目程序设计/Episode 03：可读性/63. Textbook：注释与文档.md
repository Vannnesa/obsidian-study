# Commenting and Documentation
# 注释与文档

**文档良好的代码**比文档糟糕的代码**显著更容易阅读**。好的文档能提供对所用算法的洞察，解释那些看起来令人惊讶的东西为什么是正确的，并通常让读者理解代码如何以及为什么这样工作。当然，关键在于**写出好的文档**——而不仅仅是写大量文档。

大多数文档以代码中的**注释**形式编写。我们之前见过注释，并且已经知道它们表示供人类阅读的文本，因此会被编译器忽略。在 C 和 C++ 中，注释可以用 `//` 写到行末，或者用 `/* */` 把斜杠星号和星号斜杠之间的所有内容都变成注释。

```c
// 这里是一行注释
/* 这里，所有被包含的内容
   都是注释 */
```

理解如何写出好的文档对新手（甚至有一定经验的）程序员来说可能相当棘手。这方面的技能通常会随着你阅读别人的代码（或你自己很久没看过的代码）并发现注释特别有用、或者有所欠缺——你希望注释能解释的东西——而提高。以下是一些帮助你写出更好文档的**好的经验法则**：

## Document large-scale design
## 记录大型设计

当你设计更大的程序时，你会有多个部分拼在一起。描述它们如何拼在一起。模块之间的**接口**是什么？整个系统的**不变量**是什么？

## Describe Each Component
## 描述每个组件

对于系统中的每个组件（函数、对象（如果你学到 C++）、或文件），在开头写一条描述它的注释。首先描述**接口**，供那些只需要使用该组件、不需要了解其实现细节的人阅读。对于函数，描述每个参数的含义，以及对其值的任何限制。描述函数返回什么。如果它有任何**副作用**，解释它们。

接着描述**实现细节**，供需要修改它的人阅读。如果它使用了众所周知的算法，说明这一点。如果它使用你自己设计的算法，解释该算法如何工作。

## Do Not Comment The Obvious
## 不要注释显而易见的内容

一个常见的错误是认为只要写很多注释就是好文档。然而，描述显而易见内容的注释是**适得其反的**——它们让代码变得杂乱，却没有提供任何有用信息。考虑以下例子：

```c
int sumNums (int n) {
  int total = 0;  // 声明 total，设为 0
  for (int i = 0; i < n; i++) { // for 循环  
    total = total + n; // 把 n 加到 total 上
  }
  return total; // 返回 total
}
```

这里，程序员写了四条注释，但没有一条对理解代码有任何有用的贡献。任何理解 C 如何工作基础的人，只需看一眼代码就能立刻得到相同的信息。

在函数开头写一条更好的注释会提供更多信息：

```c
/* 把从 0 到 n（不包括 n）的数字相加，并
 * 返回总和 
 */
int sumNums (int n) {
  int total = 0;
  for (int i = 0; i < n; i++) { 
    total = total + n;
  }
  return total;
}
```

## Explain The Unexpected
## 解释意外情况

如果你的代码包含不寻常的东西，例如一条正确但看起来可能错误的语句，你应该记录为什么那条语句是正确的。当不熟悉代码的人阅读它时，这些文档能让他们不必怀疑代码中不寻常的方面是不是错误——他们可以直接阅读解释，而不必试图弄清楚它是否坏了。一般来说，如果你认为有人会问“它为什么那样做？”或“那样对吗？”，你应该**抢先**用注释回答那个问题。

考虑以下带有有用文档的代码示例：

```c

 * array（一个 int 数组）
 * n（'array' 中元素的数量）

 * 这里使用的排序算法是广为人知的“快速排序”。
 * 详情见
 * - "All of Programming" (Hilton + Bracy), 第 26 章，或
 * - "Introduction to Algorithms" (CLRS), 第 7 章。
 */
void sort(int * array, size_t n) {
```

代码开头从**高层**描述了函数。它描述了函数的接口；如果你只需要使用该函数，仅读注释就能知道如何做。它还描述了该函数中使用的算法。在这个特定情况下，由于算法广为人知，它提供了简要描述和几个参考文献，以防读者不熟悉它。注意这个函数有点长（它不能完全放进我的终端），所以理想情况下，我们应该把其中一部分抽象到它自己的独立函数中。第 14–36 行的部分是一个很好的候选，可以提取到自己的函数中，因为它执行一个特定的逻辑任务，称为对数据进行“**分区**”（partitioning）。

在代码内部，注释描述了事情为什么或如何发生，以及看似不寻常事物背后的理由。例如，描述 `i` 初始化的注释解释了为什么它被初始化为 `-1`，这对不熟悉的读者可能令人困惑（甚至看起来像错误）。
