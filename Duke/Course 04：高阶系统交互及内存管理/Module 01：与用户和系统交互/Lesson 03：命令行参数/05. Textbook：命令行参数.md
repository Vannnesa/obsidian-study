# Command Line Arguments
# 命令行参数

我们的程序可以接受的一种输入形式是**命令行参数**（command line arguments）。正如你到目前为止使用过的许多程序所展示的，当你从命令提示符运行一个命令时，你可以在命令行上指定参数，方法是在程序名后面写上它们。例如，当你运行：

```bash
gcc -o hello hello.c
```

你正在向 `gcc` 传递三个参数（`-o`、`hello` 和 `hello.c`）。这些参数告诉 `gcc`——它基本上是一个编译 C 程序的大型算法的实现——我们想让它解决这个问题的哪个具体实例（在这个例子中，要读取哪个 C 源代码文件，以及把生成的程序放在哪里）。

我们可以编写程序，使它们能够检查自己的命令行参数。要做到这一点，我们必须用略微不同的**签名**来编写 `main`：

```c
int main(int argc, char ** argv) {
  //……你想要什么代码就放什么代码……
}
```

这里我们看到 `main` 现在接受两个参数。第一个 `int argc` 是传入的命令行参数的**数量**（它代表 argument count，参数计数）。第二个是一个**字符串数组**，包含传入的参数（它代表 argument vector，参数向量）。`argv` 的第 0 个元素（即 `argv[0]`）包含程序在命令行上被调用时的**名称**（所以如果你写了 `./a.out`，那么 `argv[0]` 就是字符序列 `"./a.out\0"`）。我们可以在一个玩具示例中看到这种行为：

```c
#include <stdio.h>
#include <stdlib.h>
 	
int main(int argc, char ** argv) {
  printf("Hello, my name is %s\n", argv[0]);
  return EXIT_SUCCESS;
}
```

这个程序打印出它被调用时的名称，然后退出。

`argv[0]` 通常没有用，但我们必须记住它在那里，这样如果我们访问其他参数时，才能在正确的索引处找到它们。传递给程序的其他任何参数出现在 `argv[1]` 到 `argv[argc – 1]` 中。参数按它们在命令行上书写的顺序出现在数组中（所以第一个在 `argv[1]`，第二个是 `argv[2]`，依此类推）。命令行文本如何确切地划分为离散的参数由命令 shell 决定，但通常是通过在**空白字符**处分割文本来完成的（注意，程序也可以由 shell 以外的东西调用，在这种情况下，调用程序可以传递它想要的任何参数）。参数以**文本**形式传入，所以如果程序打算把某个参数解释为数字，它必须把该文本转换为数字。

我们像访问任何其他字符串数组一样访问 `argv` 的元素。我们要注意，对于期望特定数量参数的程序，它们应该先检查 `argc`，以确保用户实际提供了正确数量的参数，然后再访问 `argv` 的元素——不这样做可能导致当用户没有提供足够参数时程序发生**段错误**。

访问命令行参数最简单的模式是遍历 `argv` 的元素（适用于对所有参数做同样事情的程序）、从特定索引提取特定信息（例如，程序可能总是期望输入文件名作为 `argv[1]`，输出文件名作为 `argv[2]`），或者两者的混合（从前几个元素读取特定信息，然后遍历其余部分）。
