# Writing to Files
# 写入文件

我们可能想执行的另一个操作是**写入文件**。与从文件读取一样，写入文件有多种选择。一种选择——如果你要打印格式化文本，会很有用——是 `fprintf` 函数。这个函数的行为与熟悉的 `printf` 函数相同，只是它在其他参数之前多接受一个参数，即一个 `FILE *`，指定把输出写到哪里。

你也可以使用 `fputc` 一次写入一个字符，或使用 `fputs` 写入一个字符串而不做任何格式转换。也就是说，如果你执行 `fputs("%d")`，它会直接把 `"%d"` 打印到文件，而不是试图转换一个整数并打印结果。

最后，如果你想写入**非文本数据**，最好的选择是 `fwrite`，它的原型是：

```c
size_t fwrite(const void * ptr, size_t size, size_t nitems, FILE * stream);
```

这些参数与传给 `fread` 的非常相似，只是数据从 `ptr` 指向的**缓冲区**读出并写入流（而 `fread` 从流读取并写入 `ptr` 指向的缓冲区）。

所有这些方法都在文件的**当前位置**写入，并相应地推进它。此外，这些写入文件的方法都可能失败，其中一些会立即检测到，另一些则会稍后检测到。请参阅你所用函数的相关 man 页面，了解它们可能如何失败，以及返回什么值来表示失败。

失败可能稍后才被检测到的原因是，C 库函数可能会**缓冲**数据，而不立即请求操作系统写入它。即使应用程序进行了必要的系统调用来写入数据，操作系统也可能在内部缓冲一段时间，然后才实际把它写到下层硬件设备。不立即写入的动机是**性能**：进行系统调用有点慢，而写入硬盘相当慢。此外，当你向磁盘写入的数据量较小时，写入磁盘会变得更低效——在磁盘上定位有固定的开销，而大量写入可以分摊这些开销——所以操作系统会尽量缓冲写入，直到有足够多的数据可以一次性写入。
