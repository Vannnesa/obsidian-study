## 问题 1
假设你写了以下代码：

```c
FILE * f = fopen("myfile.txt", "w");
```

以下哪些操作可以成功对 `f` 执行？（选择所有适用项。）

[ ] `fgets`
[c] `fclose`
[c] `fprintf`
[ ] `fgetc`

模式 `"w"` 只允许写入，不允许读取，因此 `fgets` 和 `fgetc` 无法成功执行；`fprintf` 用于写入，`fclose` 用于关闭，都可以成功。
````

以下哪一项准确描述了 `fputs` 和 `fprintf` 的异同？

[ ] `fputs` 和 `fprintf` 都写入文件。然而，`fputs` 把有符号整数放入文件，而 `fprintf` 写入格式化字符串。

[c] `fputs` 和 `fprintf` 都向文件写入字符串。然而，`fprintf` 执行 `%` 格式转换，而 `fputs` 不执行。
[ ] `fputs` 和 `fprintf` 都向文件写入字符串。然而，`fputs` 在写入前如果文件不存在会在磁盘上创建一个新文件，而 `fprintf` 不会。

`fputs` 直接写入字符串，不做格式转换；`fprintf` 会解析格式字符串中的 `%` 转换。

## 问题 3
假设你的程序打开一个文件，向其中写入大量数据，然后关闭文件。

如果磁盘上没有足够空间容纳你写入的所有数据，你的程序在什么时候保证会知道这个问题？

[ ] 当 `fopen` 返回时。
[ ] 当 `fprintf`、`fwrite` 或类似函数在产生最后一个有足够空间的字节后返回时。
[c] 当 `fclose` 返回时。
[ ] 当 `fprintf`、`fwrite` 或类似函数在产生第一个空间不足的字节后返回时。

由于 C 库和操作系统可能缓冲写入数据，实际写入可能延迟到 `fclose` 时才发生，因此 `fclose` 的返回值是程序保证能得知写入失败的时机。
````
