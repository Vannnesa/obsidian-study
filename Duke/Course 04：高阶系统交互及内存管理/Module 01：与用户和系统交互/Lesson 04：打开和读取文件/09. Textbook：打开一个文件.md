# Opening a File
# 打开文件

要访问文件（无论是读取还是写入），我们必须做的第一件事就是**打开它**。打开文件会得到一个与该文件关联的**流**（stream）。流（在 C 中用 `FILE *` 表示）是一个数据序列（在这里是 `char`），可以被读取和/或写入。流有一个**当前位置**，通常在对流执行读或写操作时会前进（并且根据流所关联的对象，程序可能可以、也可能不可以任意移动它）。

通常，你会用 `fopen` 函数打开文件，它的原型如下：

```c
FILE * fopen(const char * filename, const char * mode);
```

这个函数接受两个参数，第一个是要打开的文件名。这个文件名是一个字符串（必须以空终止符结尾，并且不会被 `fopen` 修改），它是要打开文件的**路径名**。路径名可以是**绝对路径**（以 `/` [正斜杠] 开头），也可以是相对于程序当前工作目录的路径。第二个参数是文件的**模式**（mode）——文件应该为读取和/或写入而打开，如果文件不存在是否创建它，是否清除已有内容，以及从什么位置开始访问文件。通常，会为 `mode` 参数传入一个字符串字面量（例如 `"r"`）（当然，任何求值为有效字符串的表达式都是合法的）。我们稍后会详细讨论模式。

在深入讨论模式之前，先看看打开文件的效果图会很有用。下图展示了当使用 `fopen` 打开文件，并将得到的 `FILE *` 赋值给一个名为 `f` 的变量时会发生什么。这里对 `FILE` 的描绘是概念性的，因为实际的 `struct` 要复杂得多，并且不直接包含文件中的数据。然而，我们不需要知道实际的 `FILE` 结构体包含什么，只需要知道如何操作它。事实上，即使我们知道某个特定系统上 `FILE` 结构体里有什么，也不应该试图用这些信息直接访问它内部的字段，因为实现细节依赖于系统，因此我们的代码会**不可移植**。

然而，我们对 `FILE` 结构体的概念表示确实展示了典型使用中的相关部分——我们可以用这个**抽象**来思考程序会做什么，从而如何手工执行它。顶部部分显示了关于文件状态的一些信息（打开了哪个文件、它能否被读取或写入，以及程序是否尝试读过文件末尾之后的内容）。底部部分显示了文件中的数据，以及流的位置（用一个蓝色光标表示）。读和写操作将发生在当前位置（即这个蓝色光标处），并会推进它。

我们要注意，真实的 `FILE` 结构体并不包含文件名，而是包含一个**文件描述符**（file descriptor）——当程序进行打开文件的系统调用（即 `open` 系统调用）时，操作系统返回给程序的一个数字标识符。操作流的 C 库函数会把这个描述符传递给相关的系统调用，由它们为其执行底层的输入/输出操作。

`fopen` 有可能失败——例如，你请求的文件可能不存在，或者你可能没有访问它所需的权限。每当 `fopen` 失败时，它会返回 `NULL`（并适当地设置 `errno`）。在尝试使用流之前，你应该**总是检查 `fopen` 的返回值**是 `NULL` 还是一个有效的流。

## Mode
## 模式

| 模式 | 读和/或写 | 不存在时？ | 截断？ | 位置 |
|---|---|---|---|---|
| `r` | 只读 | 失败 | 否 | 开头 |
| `r+` | 读/写 | 失败 | 否 | 开头 |
| `w` | 只写 | 创建 | 是 | 开头 |
| `w+` | 读/写 | 创建 | 是 | 开头 |
| `a` | 写入 | 创建 | 否 | 末尾 |
| `a+` | 读/写 | 创建 | 否 | 末尾 |

`fopen` 的可能模式总结在上表中。第一列显示了 `mode` 字符串的可能合法值。第二列显示打开的文件能否被读取、写入或两者皆可。第三列显示如果请求的文件不存在会发生什么——对于某些模式，它会被创建（如果可能的话），对于另一些模式，调用 `fopen` 会失败。第四列显示如果文件已经存在，其内容是否会被截断为零长度——也就是说，文件已有内容是否被丢弃。最后一列显示访问从哪里开始——文件内容的开头或末尾。我们要注意，对于 `a` 模式（代表 append，追加），所有写入都会把数据写到文件末尾，即使程序显式地把当前位置移到别处。
