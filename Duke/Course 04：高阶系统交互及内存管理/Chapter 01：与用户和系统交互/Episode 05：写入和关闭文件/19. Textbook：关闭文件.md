# Closing Files
# 关闭文件

在你用完一个文件之后，应该用 `fclose` 函数关闭它，该函数有以下原型：

```c
int fclose(FILE * stream);
```

这个函数接受一个参数，指定要关闭哪个流。关闭流会把任何缓冲的写入数据发送给操作系统，然后请求操作系统关闭关联的**文件描述符**。对某个流调用 `fclose` 之后，你不能再访问它（调用 `fgetc`、`fprintf` 等是错误的，尽管具体会发生什么是未定义的）。

观察一下，`fclose` 返回一个 `int`。这个返回值表示 `fclose` 操作的成功（返回 `0`）或失败（返回 `EOF`，并相应地设置 `errno`）。`fclose` 操作可能因各种原因失败，其中最严重的情况出现在数据实际上无法写入下层硬件设备（例如磁盘驱动器）时——例如，磁盘已满，或者文件位于远程文件系统上而网络连接已丢失。对于你一直在写入的文件，`fclose` 失败是一种严重情况——它意味着你的程序试图写入的数据可能丢失。因此，你应该**总是检查 `fclose` 的返回值**，看看它是否失败。

然而，`fclose` 失败时你该怎么做，有点难回答。你不能重试，因为对你试图关闭的流执行任何操作——包括再次调用 `fclose`——都是错误的（并导致未定义行为）。不过，你具体该做什么高度依赖于情况。

在交互式程序中，你可能希望把问题告知用户，她也许能在继续之前采取纠正措施。例如，假设你在编写一个编辑器（像 `emacs`）。如果用户试图保存工作，但磁盘已满，她更愿意被告知保存失败（以及原因）。然后用户可以去释放磁盘空间，再次保存（这会涉及重新 `fopen` 文件、`fwrite` 所有数据、`fclose` 那个流——而不是重试 `fclose` 原来的流）。相比之下，如果编辑器忽略 `fclose` 的返回值并静默失败——不告知用户问题，她可能会退出，丢失所有工作。

在其他情况下，你可能不直接与用户交互（或者与一个有能力补救情况的用户交互：想象你在编写某个 web 服务——与你交互的用户通常没有能力管理系统）。你仍然会想检测问题并采取某种纠正措施。

当 `fclose` 失败时，我们不会关心复杂的纠正措施——打印一条错误消息就足够了。然而，你应该养成检查其返回值的习惯。这样，当你在处理真实程序时，你会习惯性地检查返回值，并至少思考一下失败时应该做什么。
