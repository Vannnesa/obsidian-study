# Introduction to the Operating System
# 操作系统简介

大多数与“世界”的有趣交互——从用户读取输入、在磁盘上写文件、通过网络发送数据等——都需要以普通程序自身无法执行的方式访问**硬件设备**（键盘、磁盘驱动器、网卡）。这个问题的一个关键方面是，“普通”程序不能被信任去**直接访问硬件**。如果你的程序能直接读取磁盘，那么它就可以无视用于保护不同用户文件的**权限系统**，随意读取或写入任何数据。此外，一个能直接访问磁盘的程序中的错误，可能破坏整个文件系统，摧毁系统上的所有数据。

相反，程序请求**操作系统**（OS）——负责为所有程序管理系统上所有资源的底层软件——**代替它访问硬件**。程序通过**系统调用**（system call）发出这个请求——系统调用是一种特殊类型的函数调用，它把控制权从程序转移给操作系统。操作系统在执行请求之前，会检查程序的请求是否在其权限范围内，这就是系统**强制执行安全规则**（例如文件权限）的方式。如果请求不被允许，操作系统可以向程序返回错误。另一方面，如果请求没问题，那么操作系统执行底层的硬件操作来实现它，然后把结果返回给程序。

上图描绘了程序、C 库、操作系统和硬件之间的概念关系。虽然你的 C 代码可以直接进行系统调用，但更常见的是使用 **C 库**中的函数。然后 C 库函数根据需要发起系统调用。操作系统再与硬件进行适当的交互。

例如，假设你调用 `printf` 把一个字符串写入标准输出。`printf` 函数是 C 库的一部分，它涉及大量不需要系统调用的代码：它必须扫描格式字符串中的 `%` 符号，执行适当的格式转换，构建出实际要打印的字符串。然而，在某个时刻，`printf` 必须把得到的字符串实际写入标准输出，这需要一个**系统调用**。为了完成这个任务，`printf` 使用 `write` 系统调用。

新手程序员常常对**系统调用**（把控制权转移给操作系统，请求它执行任务）和**库调用**（调用库中存在的函数，例如 C 标准库）之间的区别不够精确。例如，把 `printf` 称为“系统调用”在技术上是不正确的，尽管大多数人会理解你的意思。精确区分这两者是有用的，原因有两个。首先，你的术语越精确，在面试中（如果你在面试编程相关的工作）就显得越有知识。其次，如果你需要在 **man 页面**中查找一个函数，知道它是系统调用还是 C 库的一部分，会告诉你该查哪一节——**系统调用在第 2 节**，而 **C 库函数在第 3 节**。
