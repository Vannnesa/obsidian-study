# Errors from System Calls
# 系统调用错误

系统调用可能以多种方式失败。例如，你可能尝试读取一个不存在的文件，或者你没有权限的文件。你也可能尝试通过网络连接到一个地址无效或不可达的远程计算机（网络或远程计算机宕机）。每当这些系统调用在 C 中失败时，它们（或者更准确地说，它们在 C 库中的包装函数）会设置一个名为 `errno`（代表“**error number**”，错误编号）的**全局变量**。

我们还没有使用过**全局变量**——而且通常不鼓励使用它们——但它们其实就是作用域为整个程序的变量。它们在任何函数之外声明，并有一个不属于任何栈帧的“盒子”。你可以像读取（或写入）任何其他变量一样读取（或写入）它们。

在 `errno` 这个特定情况下，它由失败的调用设置，如果你的程序想了解更多关于调用失败原因的信息，就读取它。如果你想检查是否发生了某个特定错误，可以把它与 `errno.h` 中定义的各种常量进行比较。

你可能还希望为用户打印一条描述错误的消息。仅仅打印 `errno` 的数值通常没有用（你知道错误 2 是什么意思吗？）。幸运的是，C 库有一个函数 `perror`，它根据 `errno` 的当前值打印一条描述性的错误消息。`perror` 函数接受一个参数，一个在它的描述性消息之前打印的字符串。

注意，由于 `errno` 是全局的（整个程序只有一个），你必须小心，在测试它或调用 `perror` 之前，不要调用任何可能改变它的东西。例如，

```c
// 坏掉的代码
int x = someSystemCall();
if (x != 0) {
  printf("someSystemCall() failed!\n");  // 可能改变 errno
  perror("The error was: ");
}
```

这里，`printf` 可能改变 `errno`（它会进行系统调用），所以我们可能无法从 `perror` 得到正确的错误描述。其他代码部分可能带来意外改变，这是全局变量的危险之一，也是通常要避免它们的原因之一。
