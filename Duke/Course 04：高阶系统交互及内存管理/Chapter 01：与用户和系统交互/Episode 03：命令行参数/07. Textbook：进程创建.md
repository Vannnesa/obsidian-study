# Process Creation
# 进程创建

虽然我们不想深入太多进程创建的细节，但我们确实想简要提及几点，以确保你相信创建新程序或把命令行参数传递给 `main` 并不涉及任何魔法。当命令 shell（或任何其他程序——命令 shell 只是一个普通程序）想要运行另一个程序时，它会进行几个**系统调用**。首先，它调用 `fork` 来创建一个**新进程**。这个新进程（它是原进程的完全副本，只能通过 `fork` 系统调用的返回值来区分）然后进行另一个系统调用 `execve`，用请求的程序替换它正在运行的程序。`execve` 系统调用接受一个参数，指定要运行的二进制文件（或脚本）的文件；第二个参数指定要作为 `argv` 传递给新程序的值（必须以 `NULL` 结尾）；第三个参数指定要传递给 `envp` 的值（即使 `main` 忽略 `envp`，这些值仍然会传递给新程序，以便前面小节中提到的各种环境操作函数可以访问它们）。

当操作系统执行 `execve` 系统调用时，它会**销毁当前正在运行的程序**（该系统调用只在出错时返回），并把指定的可执行二进制文件加载到内存中。它按照预先约定的格式（**ABI**——应用程序二进制接口的一部分：操作系统与程序之间关于事物如何工作的契约）把 `argv` 和 `envp` 的值写入内存。然后内核把执行箭头设置到可执行二进制文件中指定的起始位置（在使用 `gcc` 的 Linux 上，入口点是一个名为 `_start` 的符号——但细节因平台而异）。

这个**启动代码**（它位于一个目标文件中，与你编译的任何 C 程序链接在一起——除非你明确要求不链接它）然后调用各种函数来初始化 C 库。这个启动代码还会数 `argv` 的元素来计算 `argc` 的值，并最终调用 `main`。无论 `main` 如何声明，它总是传入 `argc`、`argv` 和 `envp`——如果 `main` 声明的参数更少，它仍然接收这些参数，只是简单地忽略它们。

当 `main` 返回时，它——像所有其他函数一样——返回到调用它的函数。对于 `main` 来说，调用者就是这个启动代码。这段代码然后执行 C 库所需的任何清理工作，并调用 `exit`（退出程序），把 `main` 的返回值作为 `exit` 的参数传入——该参数指定了程序的**退出状态**。

shell（或运行该程序的其他程序）可以进行一个系统调用，等待它的“子”进程退出，然后收集它们的返回值。
