# Uninitialized Values
# 未初始化值

当我们手工执行代码时，如果某个位置尚未初始化，我们会在它的盒子里放一个 `?`。同样，当我们手工执行时，使用未初始化的值会被视为**错误**。它表明我们的程序有问题，而且我们不知道运行代码时实际会发生什么。

然而，当你运行程序时，那个位置总是有某个值，我们只是不知道它是什么。因此，当我们运行程序时，我们会得到一个值（它只是该内存位置之前恰好存在的内容），并且没有任何检查来确认该值是否已初始化。我们不会知道我们使用了未初始化的值，如果不走运，我们的程序仍然可能打印正确的输出。

使用未初始化值是“**静默**” bug 为何危险且必须修复的一个绝佳例子。我们可能在测试和调试时认为程序是对的，因为那个位置的值碰巧是正确的。然而，程序执行中的某些变化可能让这种“运气”结束，导致程序表现出错误。

破坏你“运气”的变化可能源于各种情况。例如，改变程序的输入可能导致不同的执行路径，从而以各种不同的可能方式导致未初始化值具有不同的值。另一种可能是你用优化方式编译代码，而不是用于调试。当编译器优化你的代码时，它可能把不同的变量放在相对于调试版本不同的位置。因此，这样的 bug 可能导致令人烦恼的情况：程序的调试版本看起来能工作，但优化版本却不能（即使在相同输入上）。我们甚至见过学生在将输出重定向到文件和直接打印到终端之间，未初始化位置读取到的值出现差异的问题。

Valgrind 的 **Memcheck** 工具会显式跟踪程序中每一个位的有效性，并能告诉我们未初始化值的使用情况。默认情况下，Memcheck 会在你使用未初始化值时告诉你；然而，这些错误仅限于某些使用方式。如果 `x` 未初始化，而你执行 `y = x`，Memcheck 不会报告错误，而只是指出 `y` 现在持有一个未初始化值。事实上，即使我们计算 `y = x + 3`，我们仍然不会立即得到错误。

然而，如果我们以 Memcheck 认为会影响程序行为的某些方式使用未初始化位置（或持有由未初始化位置计算出的值），它就会给我们一个错误。其中一种情况是程序的控制流依赖于该未初始化值——当它出现在 `if` 语句或循环的条件表达式中，或出现在 `switch` 语句的选择表达式中时。在这种情况下，Memcheck 会产生错误：

```text
Conditional jump or move depends on uninitialized value(s)
```

并产生一个调用栈跟踪，显示该使用发生的位置。例如，如果我们编写函数：

```c
void f(int x) {
  int y;
  int z = x + y;
  printf("%d\n", z);
}
```

Valgrind 的 Memcheck 会报告以下错误（这段代码位于 `uninit.c` 中，上面所示行之前和之后还有其他行）：

```text
==12241== Conditional jump or move depends on uninitialised value(s)
==12241==    at 0x4E8158E: vfprintf (vfprintf.c:1660)
==12241==    by 0x4E8B498: printf (printf.c:33)
==12241==    by 0x400556: f (uninit.c:7)
==12241==    by 0x400580: main (uninit.c:15)
```

这个错误表明未初始化值在 `vfprintf` 内部被使用，而 `vfprintf` 由 `printf` 调用，`printf` 由 `f`（第 7 行）调用，`f` 又由 `main`（第 15 行）调用。我们也许可以通过观察第 7 行的 `printf` 调用，看看我们做错了什么，直接修复程序。

然而，如果我们不能立刻看出问题（如果未初始化值在 Memcheck 报告错误之前已经通过一系列函数参数和数据结构传递，这很可能是常见情况），我们就需要 Memcheck 提供更多帮助。事实上，当 Memcheck 报告这类错误时，它会在输出末尾贴心地建议我们获取更多信息所需的选项：

```text
==12241== Use --track-origins=yes to see where uninitialised values come from
```

如果我们再次运行 Valgrind 并传入这个选项（`valgrind --track-origins=yes ./myProgram`），它在报告错误时会指出未初始化值是在哪里创建的：

```text
==12260== Conditional jump or move depends on uninitialised value(s)
==12260==    at 0x4E8158E: vfprintf (vfprintf.c:1660)
==12260==    by 0x4E8B498: printf (printf.c:33)
==12260==    by 0x400556: f (uninit.c:7)
==12260==    by 0x400580: main (uninit.c:15)
==12260==  Uninitialised value was created by a stack allocation
==12260==    at 0x40052D: f (uninit.c:4)
```

我们现在可以看到，该值是由栈分配（即为函数分配栈帧）创建的，并且我们得到了导致该创建的具体代码行（`f` 内部的 `int y;`）。

还有其他情况，使用未初始化值会产生如下消息：

```text
==12235== Use of uninitialised value of size 8
```

这里 Memcheck 告诉我们，我们以一种它认为有问题的方式使用了未初始化值，并且我们使用的值大小为 8 字节（即它访问了多少字节内存）。如果我们的未初始化值被传递给系统调用，我们会得到如下错误消息：

```text
==12362== Syscall param write(fd) contains uninitialised byte(s)
```

所有这些都表明同一个根本问题：我们有一个没有初始化的值。我们需要找到它（很可能通过使用 `--track-origins=yes`），并正确地初始化它。
