# Valgrind 的 Memcheck

C 编译器会针对它能判断为有问题的东西给出警告和错误。然而，编译器能做的仅限于对代码进行**静态分析**，也就是在不运行代码、不知道程序输入的情况下能做的事情。因此，有许多类型的问题是编译器无法检测的。这些问题通常通过在问题发生的测试用例上运行代码来发现。

然而，问题发生并不意味着它会为测试者产生有用的症状。有时问题发生了却没有可观察的结果，有时可观察的结果很久之后才显现，有时可观察的结果很难追溯到真正的原因。所有这些可能性都使测试和调试更加困难。

理想情况下，我们希望任何问题都能被立即检测到，并报告关于发生了什么的有用信息。当我们直接运行 C 程序时，这种情况不会发生，因为编译器没有为我们插入任何额外的检查或报告。然而，有些工具可以在我们运行程序时执行额外的检查，帮助我们测试和调试程序。其中一个工具就是 **Valgrind**，特别是它的 **Memcheck** 工具。

Valgrind 实际上是一组工具，其设计允许根据需要添加更多工具。然而，我们主要关心 **Memcheck**，它是默认工具，会执行我们需要的检查。每当你在测试和调试代码时，都应该在 Valgrind 中运行它（称为“**valgrind 你的程序**”）。虽然用 valgrind 运行程序比直接运行程序慢得多，但它对测试和调试的帮助极大。**你应该修复 valgrind 报告的任何错误，即使它们看起来不像是问题。**

要“valgrind 你的程序”，运行 `valgrind` 命令，并把你的程序名作为参数传给它（Memcheck 是默认工具）。如果你的程序接受命令行参数，只需把它们作为程序名之后的额外参数传递。例如，如果你通常会运行 `./myProgram hello 42`，就改为运行 `valgrind ./myProgram hello 42`。为了获得最大收益，你应该在编译程序时包含调试信息（给 `gcc` 传递 `-g` 或 `-ggdb3` 选项）。

当你运行 Valgrind 时，会得到大致像这样的输出：

```text
==11907== Memcheck, a memory error detector
==11907== Copyright (C) 2002-2013, and GNU GPL'd, by Julian Seward et al.
==11907== Using Valgrind-3.10.0.SVN and LibVEX; rerun with -h for copyright info
==11907== Command: ./myProgram hello 42
==11907==
==11907==
==11907== HEAP SUMMARY:
==11907==     in use at exit: 0 bytes in 0 blocks
==11907==   total heap usage: 2 allocs, 2 frees, 128 bytes allocated
==11907==
```

这里每一行以 `==11907==` 开头的都是 Valgrind 输出的一部分。注意，当你运行时，得到的数字会不同（它是进程 ID，所以每次都会变）。Valgrind 会打印一条消息告诉你它在做什么（包括它正在运行的命令），然后运行你的程序。在这个例子中，程序没有在 `stdout` 上产生任何输出；但如果它产生了，那些输出会与 Valgrind 的输出交错在一起。这里也没有 Valgrind 错误——如果有，它们会在发生时打印出来。最后，Valgrind 给出了我们动态分配和错误的摘要。最后一行显示我们“**valgrind 干净**”——没有 Valgrind 能检测到的错误。如果我们没有 valgrind 干净，即使输出看起来正确，也应该修复程序。

注意，如果我们的程序有错误，Valgrind 会报告它们并继续运行（直到达到某个错误上限）。每当你遇到多个错误时，应该**从第一个开始，修复它，然后再处理下一个**。与编译器错误非常相似，后面的问题可能是前面错误的结果。

新手程序员常有一个误解：他们应该只在调试完程序、否则认为它已经能工作之后才运行 Valgrind。然而，如果你在整个测试和调试过程中都使用 Valgrind 的 Memcheck，你会发现调试过程容易得多。你可能会发现，那个你几个小时都搞不明白的奇怪或令人困惑的 bug，实际上是由你之前没有注意到的微妙问题引起的，而 Valgrind 本可以帮你找到它。注意，Valgrind 与用 `-fsanitize=address` 编译的代码“相处不好”，所以为了 valgrind 你的代码，你应该在不带该选项的情况下编译。确保这两个工具都无法发现你代码中的任何问题，很可能是个好主意，因为它们能检测不同的问题。

我们这里只介绍基础内容，但推荐进一步阅读 Valgrind 用户手册：  
http://valgrind.org/docs/manual/manual.html  
以获取更多信息。
