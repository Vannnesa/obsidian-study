# free

与在栈上分配的内存（一旦与该栈帧关联的函数返回，它就会被释放）不同，堆上的内存必须由程序员**显式释放**。为此，C 标准库提供了 `free` 函数。

`free` 函数的签名如上图所示，它接受一个参数：需要释放的内存的**起始地址**。这个起始地址应该与 `malloc` 返回的地址匹配。作为一条好的经验法则，**每一块由 `malloc` 分配的内存，都应该在程序执行过程中稍后的某个地方由对应的 `free` 调用释放**。

当你释放内存时，你释放的那块内存会被**解除分配**，你不能再使用它。任何试图解引用指向那块内存的指针的行为都是错误的——那些指针是**悬空的**。当然，与所有悬空指针一样，具体会发生什么是未定义的。当你手工执行代码，并且需要释放内存时，你应该**擦除**正在被释放的那块内存。具体来说，如果代码写的是 `free(p)`，你应该沿着 `p` 的箭头走（它应该到达堆中的一块内存，或者是 `NULL`），然后擦除整块内存。如果 `p` 是 `NULL`，什么也不发生。如果 `p` 指向的不是堆中某一块的起始位置，那就是错误，会发生糟糕的事情（你的程序很可能会崩溃，但也可能发生更糟的情况）。

注意，`free` 只释放你要求它释放的那块内存。如果那块内存包含指向堆中其他块的其他指针，并且你也用完了那些内存，那么你应该在释放包含那些指针的内存块**之前**，先释放那些内存块。在我们的多边形例子中，我们会像这样释放一个多边形（尽管更好的做法是编写一个 `freePolygon` 函数，把两个 `free` 调用放在里面）：

```c
polygon_t * p = makeRectangle(c1, c2);
// 使用 p 的代码
//...
// 用完 p 及其 points
free(p->points);
free(p);
```

注意，先 `free(p)` 再 `free(p->points)` 是**错误的**：在第二次调用时 `p` 已经悬空，因此我们不应该解引用它。
