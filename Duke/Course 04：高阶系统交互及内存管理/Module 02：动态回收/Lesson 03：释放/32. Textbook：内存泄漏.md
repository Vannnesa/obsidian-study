# Memory Leaks
# 内存泄漏

当你**丢失了对某块内存的所有引用**（也就是说，没有任何指针指向它），而这块内存仍然处于已分配状态时，你就**泄漏了内存**（或者可以说你的程序出现了**内存泄漏**）。对于你在本书中编写的小程序来说，内存泄漏可能看起来不是什么大问题——程序退出时，操作系统会释放分配给程序的所有内存，所以即使有几百字节闲置着，谁在乎呢？

在最多运行几秒钟的小程序中，内存泄漏可能影响不大。然而，在真实程序中，内存泄漏会带来显著的**性能问题**。你有没有发现某些程序打开时间越长就越慢？也许你有一个程序，如果打开一两天，就不得不重启，因为它慢得令人烦躁。一个合理的猜测是，编写它的程序员很马虎，程序在泄漏内存。

然而，你不会成为一个马虎的程序员。你会释放你所有的内存。当你编写程序时，你应该在 `valgrind` 中运行它，并确保在末尾得到以下消息：

```text
All heap blocks were freed -- no leaks are possible
```
