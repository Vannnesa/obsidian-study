# Invalid Reads and Writes
# 无效的读取和写入

Valgrind 的 Memcheck 工具还会对你程序中的内存访问（例如通过指针）执行比正常运行时**更严格的检查**。特别地，Memcheck 会跟踪每个地址在任意特定时刻是否**有效**（以及该地址是否包含已初始化的数据）。任何对无效地址的访问都会导致 Memcheck 报错。

例如，假设我们编写了以下（坏掉的）代码：

```c
// 严重损坏——返回一个悬空指针！
int * makeArray(size_t sz) {
  int data[sz];
  for (size_t i = 0; i < sz; i++) {
    data[i] = i;
 	}
 	return data;
}
```

根据我们用这个函数的返回结果做什么，我们的代码可能看起来能工作，也可能给我们相当奇怪的错误。如果我们在调用函数（例如 `main`）中读取这个数组，那么我们可能不会立即观察到任何坏现象（然而，如果我们调用其他函数，数组中的值可能会“神秘地”改变）。如果我们在 Valgrind 中运行这样的代码，我们可能会得到如下错误：

```text
==24640== Invalid read of size 4
==24640==    at 0x40060C: main (dangling.c:16)
==24640==  Address 0xfff000340 is just below the stack ptr.
```

这里，Memcheck 告诉我们，我们试图从一个无效的（当前未分配的）内存位置读取 4 个字节。它给出了无效读取发生位置的调用栈跟踪（在这个例子中，它在代码第 16 行，这里没有显示）。Memcheck 告诉我们哪个地址出了问题，并尽可能提供该地址相对于有效内存区域的位置信息。在这个特定情况下，地址刚好在**栈指针**下方，意味着它位于一个最近返回的函数的栈帧中。如果我们改为写入该地址，我们会得到关于 “Invalid write of size X”（大小为 X 的无效写入）的消息。

注意，Memcheck **不能检测所有与内存相关的错误**（尽管它能检测许多否则会被漏掉的错误）。如果调用了另一个函数（它会在相同地址范围内分配一个栈帧），那块内存会再次变为有效，Memcheck 就无法分辨通过这个指针访问它是不正确的。同样，Memcheck 可能无法检测**数组越界**错误，因为被不当访问的内存位置可能仍然是程序可以访问的有效地址（例如，是某个其他变量的一部分）。

注意，使用 `-fsanitize=address` 可以找到很多 Memcheck 无法发现的这类问题。原因是 `-fsanitize=address` 强制在变量之间插入额外的未使用位置，并用它使用的有效性位将它们标记为不可读。因为现在变量之间有了无效空间，由 `-fsanitize=address` 插入的检查就能检测到它们之间的访问，例如越出一个数组的边界。
