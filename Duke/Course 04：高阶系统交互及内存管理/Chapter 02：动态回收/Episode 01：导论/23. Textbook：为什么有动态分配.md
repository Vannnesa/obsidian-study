# Motivation for Dynamic Allocation
# 动态分配的动机

回想一下这个任务：编写一个函数，接受一个整数，创建一个由该整数指定大小的数组，初始化每个字段，并把数组返回给调用者。用我们目前掌握的工具，我们的代码（它不会工作！）会像这样：

```c
// 坏掉的代码：不要这样做
int * initArray(int howLarge) {
  int myArray[howLarge];
  for (int i = 0; i < howLarge; i++) {
    myArray[i] = i;
 	}
  return myArray;
}
```

这段代码不能工作的原因是，数组是在**栈**上创建的。栈上的变量只在函数结束之前存在，到那时栈帧基本上就消失了。

虽然从这个例子看，能够创建一个数组并返回它似乎不那么重要，但程序员常常想编写执行更复杂创建任务的函数（并且让结果在创建它们的函数之后仍然存在）。假设你需要从文件读取信息（可能格式很复杂）。你可能想编写一个函数来读取信息，分配内存以某种数组和结构体的组合来保存结果，并把结果返回给调用者。幸运的是，有一种方法可以做到这一点：**动态内存分配**。

动态内存分配允许程序员请求在**堆**（heap）上分配特定数量的内存（如下图中的紫色部分）——而不是栈。因为内存不在栈帧中，所以函数返回时它不会被释放。相反，程序员必须在她用完内存后**显式地释放它**。

动态内存分配涉及**分配内存**（用 `malloc` 函数），以及在你不再需要时**释放那块内存**（用 `free` 函数）。程序员可能还希望把一块内存**重新分配**为不同的大小（例如，你可能认为 8 个元素的数组足够，然后读取一些输入后发现需要 16 个）。`realloc` 函数允许程序员做到这一点——请求标准库分配一块新的（更大或更小的）内存，把原内容复制到新的，并释放旧的（尽管如果库能在原地扩展块，它可能会优化这个过程）。对于这三个函数，都要包含 `<stdlib.h>`。我们还将看到一个很棒的函数 `getline`，它使用动态分配来读取任意长度的字符串。
