# Mutable Strings
# 可变字符串

当我们想要修改字符串时，需要让字符串驻留在**可写内存**中，例如函数的栈帧，或者由 `malloc` 动态分配的内存（你将在课程 4 中学习）。为了在函数栈帧中为字符串腾出空间，我们需要声明一个 `char` 数组，其空间足以容纳所有字符，再加上它的**空终止符**。

我们可以这样声明并初始化字符数组：

```c
char str[] = "Hello World\n";
```

这段代码的行为完全就像我们写了：

```c
char str[] = {'H', 'e', 'l', 'l', 'o', ' ',
              'W', 'o', 'r', 'l', 'd', '\n', '\0'};
```

也就是说，它声明了一个变量 `str`，它是一个包含 13 个字符的数组（记住，如果我们提供了初始化器，编译器可以据此确定大小，那么数组大小可以是隐含的），并通过把字符串 `"Hello World\n"` 的字符（包括空终止符）复制到该数组来初始化它。更明确一点，可以认为这段代码做了：

```c
char str[13];
str[0]  = 'H';
str[1]  = 'e';
str[2]  = 'l';
str[3]  = 'l';
str[4]  = 'o';
str[5]  = ' ';
str[6]  = 'W';
str[7]  = 'o';
str[8]  = 'r';
```

下图说明了将 `str` 声明为 `const char * str` 与声明为 `char str[]` 之间的区别。图中展示了声明为指向字面量的指针的字符串（左）与声明为由字面量初始化的数组（右）之间的区别。

我们可以用显式大小声明数组 `str`，但必须小心——如果我们没有为空终止符留出足够空间（即声明为 `char str[12]="Hello World\n";`），编译器不会抱怨。相反，它会完全按照我们的要求初始化字符数组，但末尾不会放置 `'\0'`。编译器允许这种行为，因为它构成了一个完全有效的字符数组，即使它不是一个有效的字符串。如果我们只以访问那 12 个字符的方式计算该数组，程序没问题。然而，如果我们把该数组用于任何期望真正字符串（即末尾有空终止符的字符串）的地方（例如传递给 `printf` 或你很快会学到的任何字符串库函数），那么数组就会被**越界访问**。

未能终止字符串可能不会总是在测试中出现——你可能“走运”，下一个内存字节本来就是 0。虽然这看起来不错——你的程序“能工作”——但它实际上是一种相当**危险**的问题。你可能测试程序一千次都看不到任何错误，然后部署它，却让它崩溃或产生不正确的结果。我们强烈建议使用 `valgrind` 之类的工具，它们能够检测这类错误。

然而，为你的字符串请求比所需更多的空间是完全可以的。例如，`char str[100] = "Hello World\n";` 完全合法。如果我们计划向字符串添加内容、使其变长，我们可能希望以这种方式请求额外空间。当然，每当我们这样做时，必须确保我们有足够空间容纳我们可能想让字符串保存的任何内容。（记住，程序员负责跟踪她数组的大小。**没有办法检查一个数组并推导出它的大小**。）
