# Array of Strings
# 字符串数组

正如我们之前提到的，**字符串数组本质上就是多维字符数组**，因为字符串本身实际上只是字符数组。相应地，所有相同的规则都适用于字符串数组，我们可以使用想要的任何一种表示方式。然而，由于字符串数组相当重要（除此之外，程序可以通过字符串数组访问其命令行参数），因此值得明确讨论它们。

考虑以下两条语句，每一条都声明了一个多维 `char` 数组，并用大括号包裹的字符串字面量数组初始化它：

```c
char strs[3][4] = {"Abc", "def", "ghi"};
char chrs[3][3] = {"Abc", "def", "ghi"};
```

观察这两条声明之间的区别在于数组**第二维的大小**——第一条语句中是 4，第二条中是 3。第一条语句（声明 `strs`）包含了**空终止符**的空间，这是使字符序列成为有效字符串所必需的。第二条语句（声明 `chrs`）不包含这样的空间，只存储写出的字符（没有空终止符）。下图说明了这两条语句的效果。

（图）

第二条语句是正确的前提是（且仅当）我们打算只把 `chrs` 用作多维字符数组，而不把它用于任何期望以空终止符结尾的字符串的地方。由于第二条语句构成了一个有效的多维 `char` 数组，它并不非法，也不会产生错误或警告。这种行为与我们之前讨论的仅声明字符数组并用字符串字面量初始化它们时非常相似。然而，一个显著区别是，在多维情况下，**我们不能省略第二维的大小**（即每个字符串中的字符数），因为 C 只允许我们省略多维数组的**第一维**。

如果你声明一个多维 `char` 数组来保存不同长度的字符串，那么你必须根据**最长字符串的长度**来确定第二维的大小。例如，我们可能声明以下数组：

```c
char words[4][10] = {"A", "cat", "likes", "sleeping."};
```

在这个例子中，`words` 需要 40 个字符的存储空间，尽管用于初始化它的字符串只占用 22 个字符。这种表示浪费了一些空间。虽然在这个例子中这种浪费可能不显著，但如果我们处理的是数百万个长度差异很大的字符串，我们可能会浪费数兆字节。

（图：字符串数组，即指向以空终止符结尾的 `char` 序列的指针数组。）

我们也可以改用**指针数组**表示法来表示字符串数组。正如我们之前讨论的，用指针数组表示多维数据允许我们拥有不同长度的项，这自然解决了浪费空间的问题。要以这种方式表示我们的字符串数组，我们可以像下面这样声明并初始化 `words`：

```c
const char * words[] = {"A", "cat", "likes", "sleeping."};
```

观察这里我们把 `words` 声明为 `const char *` 的数组——数组的元素是指向 `const char` 的指针，因此它们指向的字符不能被修改。我们应该包含 `const`（并且必须包含它才能符合 const 正确性），因为我们已经表明 `words` 应被初始化为指向字符串字面量的指针，而字符串字面量位于**只读内存**中。上图说明了 `words` 的布局。

我们要注意，通常会在字符串数组末尾加上一个 **`NULL` 指针**，像这样：

```c
const char * words2[] = {"A", "cat", "likes", "sleeping.", NULL};
```

这个约定很常见，因为它允许人们编写**事先不知道数组中有多少元素**的循环来遍历数组。相反，循环可以有一个检查 `NULL` 的条件，像这样：

```c
const char ** ptr = words2;
while (*ptr != NULL) {
  printf("%s ", *ptr);
  ptr++;
}
printf("\n");
```

手工执行这段代码将是一个有益的练习，以确保你理解其中涉及的所有概念。然后你可以把它放进源文件（带有适当的 include，并放在 `main` 内部），以确保你推导出了正确的答案。
