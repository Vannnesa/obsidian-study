# Sorting Functions
# 排序函数

函数指针作为参数的另一个例子是**通用排序函数**——一个能排序任何类型数据的函数。排序数组就是把该数组的元素按递增（或递减）顺序排列的过程。排序数组是程序中的常见任务，因为有序数据比无序数据能更高效地访问。我们稍后会形式化这种效率概念，但现在，想象一下在按字母顺序（即有序）排列的图书馆里找书，与在没有任何特定顺序存放的图书馆里找书的区别。

正如我们学习更多排序知识时会看到的，有许多不同的排序算法，但它们都不关心数据的具体类型，只关心一份数据是否“小于”、“等于”或“大于”另一份数据。相应地，我们可以通过让通用排序函数接受一个参数——指向比较数组两个元素的函数的指针——来创建一个能排序任何类型数组的函数。事实上，C 库提供了这样一个函数（它按升序排序——从小到大）：

```c
void qsort(void *base, size_t nmemb, size_t size, 
                int (*compar)(const void *, const void *));
```

这个函数的第一个参数 `void * base` 是要排序的数组。回想一下，`void *` 是“指向未指定类型数据的指针”——允许 `qsort` 接受任何类型的数组。第二个参数 `size_t nmemb` 指定数组中元素（或成员）的数量（回想一下，`size_t` 是适合用于描述事物大小的无符号整数类型）。第三个参数 `size_t size` 指定数组每个元素的大小——即每个元素在内存中占多少字节。这个信息是必需的，否则 `qsort` 无法判断数组的一个元素在哪里结束、下一个元素在哪里开始。最后一个参数是我们在这次讨论中最感兴趣的——`compar` 是一个指向函数的指针，该函数接受两个 `const void *` 并返回一个 `int`。这里，两个 `const void *` 指向要比较的两个元素（它们是 `const`，因为比较函数不应修改数组）。如果第一个指针指向的东西大于第二个指针指向的东西，函数返回正数；如果它们指向相等的东西，返回 `0`；如果小于，返回负数。

对 `qsort` 的这个描述可能看起来信息量很大，但通过看几个例子会更容易理解。这两个例子都将是围绕 `qsort` 的**包装函数**——做一些很少或没有实际计算，但提供更简单接口的小函数。第一个例子是排序 `int` 数组的包装：

```c
int compareInts(const void * n1vp, const void * n2vp) {
  const int * n1ptr = n1vp; // 转换回 int* 以便解引用
  const int * n2ptr = n2vp;
  return *n1ptr - *n2ptr;   // 两个数相减就是比较它们
}

void sortIntArray(int * array, size_t nelements) {
  qsort(array, nelements, sizeof(int), compareInts);
}
```

首先，我们编写一个比较函数 `compareInts`，它的行为与 `qsort` 的接口兼容——它接受声明为 `const void *` 的指针，并返回 `int`。由于这个函数只打算在排序 `int` 数组时使用，它把 `const void *` 转换为 `const int *`，并解引用它们以获取数组中的实际 `int`。这两个 `int` 相减得到的结果符合 `qsort` 函数的期望（如果第一个更大则为正，相等为 `0`，第一个更小则为负）。

一旦这个函数写好，我们就可以编写包装 `qsort` 函数的 `sortIntArray` 函数。观察 `sortIntArray` 如何不做任何实际计算（它只是调用 `qsort` 来做所有工作），但提供了简单得多的接口（你传给它的是一组 `int` 数组和数组中元素的数量；你应该能够无需任何解释就使用这个函数来排序数组）。`sortIntArray` 函数把它的参数作为前两个参数传给 `qsort`，然后传 `sizeof(int)` 作为第三个参数，因为数组的每个元素大小都是 `sizeof(int)` 字节（可能是 4，但正确的写法是用 `sizeof` 运算符，以防你在某个不是 4 的地方编译它）。对于第四个参数，函数传一个指向 `compareInts` 的指针——回想一下，函数名就是指向该函数的指针。然后 `qsort` 函数会调用 `compareInts` 来确定数组中元素的相对顺序。

我们可以用类似的方式为其他类型使用 `qsort`。例如，我们可以编写一些类似的函数来排序字符串数组（`const char *` 的数组）：

```c
int compareStrings(const void * s1vp, const void * s2vp) {
  // 第一个 const：s1vp 实际上指向 (const char *)
  // 第二个 const：不能改变 *s1vp（它是一个 const void *）
  const char * const * s1ptr = s1vp;
  const char * const * s2ptr = s2vp;
  return strcmp(*s1ptr, *s2ptr);
}

void sortStringArray(const char ** array, size_t nelements) {
  qsort(array, nelements, sizeof(const char *), compareStrings);
}
```

我们再次从编写一个符合 `qsort` 所需接口的比较字符串的函数开始。这个函数 `compareStrings` 看起来与 `compareInts` 大致相同。主要区别是我们使用 `strcmp` 来执行字符串比较。我们之前见过 `strcmp` 用于测试两个字符串是否相等，然而，它会根据字符串的顺序返回正/零/负值，正如 `qsort` 所期望的。

注意，传入的指针是指向数组中元素的指针（也就是说，它们指向数组中的盒子），即使那些元素本身也是指针（因为它们是字符串）。当我们将它们从 `void *` 转换回来时，必须注意转换为正确的类型——这里是 `const char * const *`——并适当地使用它们，否则我们的函数会以某种方式坏掉。例如，考虑以下**坏掉的**代码：

```c
// 坏掉的，不要这样做！
int compareStrings(const void * s1vp, const void * s2vp) {
  const char * s1 = s1vp;
  const char * s2 = s2vp;
  return strcmp(s1, s2);
}
```

这段代码实际上会编译通过，没有任何错误或警告，但不会正确工作。这是任何时候使用 `void *` 都存在的危险——这种灵活性给了你“足以吊死自己的绳子”，因为你无法保证会以正确的方式使用指针。正如我们稍后会看到的，C++ 的类型系统中有一些特性，允许我们以安全得多的方式拥有通用函数。

我们几乎可以在任何能使用其他类型的地方使用函数指针——不仅是作为参数的类型，还可以作为变量的类型、数组中元素的类型，或结构体中的字段。事实上，正如我们稍后会看到的，结构体中的函数指针是**面向对象编程**的核心，尽管面向对象语言对普通程序员隐藏了这个实现细节。
