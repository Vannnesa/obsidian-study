# String Literals
# 字符串字面量

我们到目前为止已经见过**字符串字面量**——写在引号中的字符序列，例如：

```c
"Hello World\n"
```

现在，既然我们理解了**指针**，我们就可以理解它们的类型：`const char *`，也就是说，**指向不可修改字符的指针**（回想一下，这里的 `const` 修饰的是所指向的 `char`）。

也就是说，如果我们想要一个指向字符串字面量的变量，我们可能会写：

```c
const char * str = "Hello World\n";
```

这段代码声明并初始化了变量 `str`，所以让我们看一下它的效果图：

![[Pasted image 20260919101834.png]]

上图说明了这样一条语句的效果，以及字符串在内存中的布局。`str` 是一个指针，指向一个**字符数组**。这些字符按字符串的顺序出现，后面跟着**空终止符**字符 `'\0'`（注意，我们不需要在字符串字面量中写下这个字符——编译器只为字面量自动添加它）。在字符串的概念表示下方，图中展示了它的数值表示——字符串只是内存中的一串字节（8 位数字），最后一个字节的数值为 0（别忘了：**一切都是数字**！）。

注意我们使用了 `const`，表明我们不能修改 `str` 所指向的字符（也就是说，对 `str[i]` 赋值会导致编译器错误）。如果我们忘了 `const` 修饰符，不幸的是，代码仍然会编译（我们可以用 `-Wwrite-strings` 收到这类错误的警告，它默认不随 `-Wall` 启用，因为许多程序员对 `const` 很马虎——这并不是说你也应该马虎）。然而，如果我们省略 `const` 并尝试修改字符串，程序会因**段错误**（segmentation fault）而崩溃。

如果你尝试修改字符串字面量，程序会崩溃的原因是字符串字面量的数据存储在**静态数据区**的**只读部分**。下图展示了指向上图字符串字面量的变量，在你之前学过的“内存图”上下文中的位置。

![[Pasted image 20260919101859.png]]

注意，字符串字面量通常放在静态数据区的只读部分，如上所示。

字符串字面量的数据（组成字符串的实际字节）在整个程序的生命周期中都驻留在静态数据区的只读部分——从它被加载到内存直到程序退出。这些数据由**加载器**（loader）放入内存——加载器是操作系统的一部分，它从磁盘读取可执行文件并适当地初始化其内存。加载器知道为字符串字面量写入什么（以及它们应该放在内存中的哪里），因为编译器把描述数据段内容的信息写入了可执行文件。加载器完成内存初始化后，会在**页表**（page table）中将静态数据区的只读部分标记为不可写——页表是操作系统维护的、用于向硬件描述程序内存的结构。

尝试写入只读内存部分的行为与写入无效内存区域非常相似——它会导致硬件**陷入**操作系统——把执行控制权从你的程序转移到操作系统内核（从概念上讲，硬件把执行箭头从你的程序中拿走，放进操作系统中的一个特定函数，同时记下执行箭头原来在你的程序中的位置，以防操作系统想把控制权交还给你的程序）。然后操作系统看到程序试图以无效方式访问内存，并用**段错误**杀死它。

如果你想了解更多关于页表以及操作系统如何处理内存的知识，我们鼓励你在完成本专项课程后学习一门计算机组成课程。

编译器把字符串字面量放入只读内存区域，是因为该字面量可能被**重用**，因此不应被修改。考虑以下代码：

```c
char * str1 = "Hello";
str1[0] = 'J';  // 这会崩溃，但假设它没有
…
…
char * str2 = "Hello";
printf("%s\n", str2);
```

字面量 `"Hello"` 的两次出现都求值为指向该字符串字符存储位置的指针。编译器可以自由地把两个相同的字符串字面量放在同一个位置，这意味着 `str1` 和 `str2` 可能指向同一块内存。如果允许修改这块内存，打印 `str2` 就会打印 `"Jello"`，这会令人困惑。更糟的是，修改字符串字面量可能引发各种问题，从奇怪的行为到安全问题。注意，即使字面量在程序中只出现一次，它也可能被多次重用（在循环内部、在不止一次被调用的函数中，等等）——在这种情况下，作为程序员，我们的期望是字面量始终是我们写的内容，没有被之前的代码改变。
