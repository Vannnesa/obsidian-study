# Dangling Pointers
# 悬空指针

当你用数组编写代码时，你可能会忍不住想从函数中返回一个数组（毕竟，当数组是你的答案时，这样解决问题很自然）。然而，我们必须小心，因为本章中我们创建的数组的存储空间位于**栈帧**（stack frame）中，因此会在函数返回后被**释放**。命名数组的表达式，其值只是一个指向那块空间的指针，所以复制到调用函数的只是一个指向**不再存在**的东西的箭头。每当你有一个指向内存已被释放的东西的指针时，它被称为**悬空指针**（dangling pointer）。**解引用悬空指针会导致未定义行为**（因此代表你代码中的一个严重问题），因为你不知道箭头末端是什么值。

如果我们尝试编译视频中的代码，并且使用了这种有问题的方式，编译器会警告我们代码坏了：

```text
warning: function returns address of local variable [-Wreturn-local-addr]
   return myArray;
```

然而，你应该理解编译器为什么会给出这个警告，并且**永远不要编写表现出这种坏行为的代码**，而不是依赖编译器去发现它。编译器检测这类问题的能力相当有限。考虑以下代码，它仍然是坏的，并且与视频中的代码有完全相同的效果：

```c
// 仍然是坏的
int * initArray(int howLarge) {
  int myArray[howLarge];
  for (int i = 0; i < howLarge; i++) {
    myArray[i] = i;
  }
  int * p = myArray;
  return p;
}
```

即使代码同样坏，`gcc` 也不产生任何警告。如果你手工执行对这个函数的一次调用（推荐这样做），你会发现它的返回值是悬空的。

关于悬空指针，有一件事要特别警惕：**有时你可以使用它们而不观察到任何问题**——你的代码仍然是坏的，只是看起来（甚至行为上）不坏。代码看起来没问题尤其危险，原因有两个。首先，当我们的代码中有问题时，我们想找到它。我们想修复它，使代码正确，并且内部没有潜伏的危险。其次，“但我以前那样做没问题”这种效应对新手很危险——如果你学到某件事是没问题的，你就会一直做下去。你不想养成坏习惯。

要理解为什么你有时只看到问题，记住存储在内存中的值会一直保留在那里，直到被程序改变——而一个已释放的内存位置可能不会立即被重用。一旦函数返回并且它的栈帧被销毁，属于那个栈帧的内存位置不会立即被重用，直到有更多值必须放到栈上。如果我们调用另一个函数，它的栈帧会被放在下一个可用的栈槽中，覆盖最近释放的内存。只有到这时，与已释放栈帧相关的值才会改变（由于对新栈帧中变量的赋值）。现在通过悬空指针写入内存会以不可预测的方式改变那个栈帧中的变量。注意，即使你没有调用另一个函数，使用指向已释放栈帧的悬空指针也是不安全的——尽管大多数栈分配来自调用函数，但没有任何东西保证这些是栈被使用的唯一方式。
