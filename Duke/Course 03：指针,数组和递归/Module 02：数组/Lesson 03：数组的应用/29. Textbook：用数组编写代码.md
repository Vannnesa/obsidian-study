# Writing Code with Arrays
# 用数组编写代码

当我们用数组编写代码时，需要寻找访问数组的模式。一个常见的模式是**按顺序访问数组的每个元素**（第 0 个，然后是第 1 个，等等）。这种模式通常自然地适合用 `for` 循环对数组元素进行计数。然而，我们可能还有其他模式——一如既往，我们应该自己动手解决问题，写下我们做了什么，并寻找模式。

如果我们有复杂的数据（例如，**结构体数组**，其中又包含数组），那么仔细思考如何命名我们想要操作的特定盒子就非常重要。对于具有复杂结构化数据的问题，画出带有适当指针和数组的图，可能是我们自己动手做一个问题实例（**步骤 1**）的重要方面。然后，当我们准确写下我们做了什么（**步骤 2**）时，我们可以仔细思考如何命名我们操作的每个盒子。记住，有时一个盒子会有**多个名字**，在这种情况下，我们需要思考我们是如何选择那个盒子的——我们走了什么“路线”到达它，以确定哪个名字最合适。如果我们不确定，应该记下我们能想到的该盒子的其他名字；然后在**步骤 3** 中，我们可能会意识到我们更喜欢另一种命名同一个盒子的方式，因为它与我们算法中其他“几乎重复”的部分形成了更一致的模式。

## Index of Largest Element
## 最大元素的索引

在我们的激励性例子（破解简单密码系统）中，我们讨论了解决**找出 26 个数字中最大值**的问题。既然我们了解了数组，我们就可以实现这个函数的一个好得多的版本。我们还可以让函数稍微更通用一些——不是只操作 26 份数据，而是让它能处理任意大小的数组。视频 **“Index of Largest Element”** 逐步演示了这个例子。
