# Array Declaration and Initialization
# 数组的声明与初始化

**数组**（array）是同一类型元素的序列（例如，`int` 的数组是 `int` 的序列）。当创建数组时，程序员指定它的**大小**（即序列中元素的数量）——所以我们可能为频率统计的例子创建一个包含 26 个 `int` 的数组。如果我们想声明一个包含 4 个 `int`、名为 `myArray` 的数组，我们会写：

```c
int myArray[4];
```

注意，这行代码看起来就像任何其他变量声明，只是变量名后面有 `[4]`——这指定我们正在声明一个大小为 4 的数组（即序列中有 4 个 `int`，而不是只有一个 `int`）。当我们做这个声明时，我们得到的语义与我们习惯的略有不同。变量名（在这个例子中是 `myArray`）是一个**指向组成数组的 4 个盒子的指针**。与其他变量不同，`myArray` **不是 `lvalue`**——我们不能改变它指向的位置。相反，它只是命名了一个指向数组中第一个盒子的指针。从 **C99**（1999 年定义的 C“版本”）开始，数组可以用非常量表达式作为大小来声明，即我们可以写 `int myArray[x];`，其中 `x` 是之前声明（并初始化！）的整数变量。你通常会想给 `gcc` 加上命令行选项 `--std=gnu99`，以启用 C99 中定义的功能——这就是其中一个特性。

这个图描绘了由 `myArray` 声明产生的包含 4 个 `int` 的数组。注意有 4 个盒子（尚未初始化），而 `myArray` 没有自己的盒子——它只是一个指向第一个盒子的箭头的名字。

上图说明了这个声明的效果。我们创建了数组（它有 4 个未初始化的 `int` 盒子），而 `myArray` 命名了一个指向它的指针。与其他变量不同，我们画 `myArray` 时不带它自己的盒子，以强调 `myArray` 不是 `lvalue`——我们不能改变它。与其他变量一样，我们可以在声明数组的同一行初始化它。然而，由于数组持有多个值，我们把初始化数据写在**大括号**内。例如，我们可能写：

```c
int myArray[4] = {42, 39, 16, 7};
```

你可能认为在初始化器中写错元素数量（例如上面的例子中写 5 或 7）会导致编译器错误，然而，**如果你在初始化器中写了太多元素，你只会收到一个警告**。如果你写的元素太少，编译器会默默地用 `0` 填充剩余的元素。这种行为对于**将整个数组零初始化**来说是一个有用的特性——我们只需在大括号中写一个 `0`，编译器就会填充与数组元素数量一样多的零：

```c
int myArray[4] = {0}; // 将所有元素初始化为 0
```

注意，大多数编译器也会接受 `int myArray [4] = {};`，然而，如果你用 `-pedantic` 编译，`gcc` 会对此发出警告，因为语言标准并不严格允许它。

如果我们提供了初始化器，我们也可以**省略数组大小**，改为写空方括号——编译器会数初始化器中的元素，并填入数组大小：

```c
int myArray[] = {42, 39, 16, 7}; // 编译器算出 [4]
```

我们还要注意，你可以用类似的语法初始化**结构体**。例如，下面的代码会把 `p` 的第一个字段初始化为 `3`，第二个字段初始化为 `4`：

```c
point p = {3, 4};
```

然而，对于结构体，这种初始化形式**非常脆弱**——如果你在这两个字段之前或之间添加另一个字段，你就不再以你打算的方式初始化字段了。在 C99 中（例如，你用 `-std=gnu99` 编译时得到的），你可以**指定**你正在初始化哪个元素：

```c
point p = { .x = 3, .y = 4};
```

现在，如果结构体中添加了另一个字段，它会被零初始化，而 `x` 和 `y` 字段仍然会被正确初始化。

如果你正在初始化一个**结构体数组**，这两种技术配合得特别好（**可组合性**的一个例子）。例如，我们可以声明并初始化一个包含三个点的数组：

```c
point myPoints[] = { {.x = 3, .y = 4},
                     {.x = 5, .y = 7},
                     {.x = 9, .y = 2} };
```
