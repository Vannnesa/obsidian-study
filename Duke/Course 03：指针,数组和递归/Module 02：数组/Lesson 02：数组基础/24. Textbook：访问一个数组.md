# Accessing an Array
# 访问数组

我们可以用几种不同的方式访问数组的元素（实际上它们在底层是相同的！）。我们已经知道，数组名是指向其第一个元素的**指针**，我们可以对指针做算术，也可以解引用指针来访问箭头末端的数据。我们可以把这些概念结合起来，看到访问数组元素的一种方式。

使用**指针算术**访问数组元素是可行的，有时也是访问元素的自然方式。然而，有时我们只想要数组的第 n 个元素，声明一个指针、给它加 n、然后解引用会很笨重。我们可以通过**索引**数组来更简洁地实现这个目标。当我们索引数组时，我们写数组名，后面跟着包含我们想引用元素编号的方括号：例如 `myArray[3]`。索引数组命名了序列中的特定盒子，可以用作 `lvalue` 或 `rvalue`。重要的是要注意，在 C（以及 C++ 和 Java）中，**数组索引是从零开始的**——数组的第一个元素是 `myArray[0]`。有些编程语言使用从 1 开始的数组索引，但从 0 开始通常更常见。

我们要注意，**越界访问数组**（访问任何不存在的元素）是编译器无法检测的错误。如果你写了这样的代码，你的程序会访问某个盒子，但你不知道它实际是哪个盒子。这种行为与我们讨论指针算术时讨论的错误行为非常相似。事实上，**指针算术和数组索引在底层完全相同**，编译器把 `myArray[i]` 转换成 `*(myArray + i)`（这个定义导致了一个“愚蠢的 C 技巧”，你可以用它来迷惑朋友：`i[myArray]` 看起来很荒谬，但完全合法。为什么？`i[myArray] = *(i + myArray)`。由于加法是可交换的，这与 `*(myArray + i)` 相同，也就是与 `myArray[i]` 相同。这个冷知识除了在派对上让朋友惊叹、以及和懂一点 C 但不知道这个事实的人打赌获胜之外，完全没用。）

注意，这条规则的一个推论是，如果我们取 `&myArray[i]`，它等价于 `&*(myArray + i)`，而 `&` 和 `*` 会相互抵消（如我们之前所学，它们是逆运算符），所以它就只是 `myArray + i`。这个结果很幸运，因为它符合我们的期望：`&myArray[i]` 说“给我一个指向 `myArray` 第 i 个盒子的箭头”，而 `myArray + i` 说“给我一个指针，指向 `myArray` 所指位置之后的 i 个盒子”——这是描述同一件事的两种不同方式。
