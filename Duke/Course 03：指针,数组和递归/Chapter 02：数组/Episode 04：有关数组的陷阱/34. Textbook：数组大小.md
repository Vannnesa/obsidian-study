# 数组大小

在迄今为止的各种例子中，我们用 `int`——一种**有符号整数**，意味着它可以保存正值或负值——来表示数组的大小和索引。如果我们非常仔细地思考这种情况，可能会想：为什么要使用有符号 `int`？负的数组索引是不合法的，因为没有 `myArray[-1]`（这会是越界）。这种分析表明我们应该使用 `unsigned int`（无符号整数类型）。然而，当我们非常仔细地思考可能使用什么类型时，我们不妨问：“最正确的类型是什么？”特别地，无符号整数有各种大小——我们想要 8 位？16 位？32 位？64 位？对于一个四元素数组，这些中的任何一个都可以正常工作。然而，我们可能想编写一个更通用的数组操作函数，能处理任何大小的数组。在这种情况下，我们想用多大的无符号整数来描述数组的大小和/或对它进行索引？

在 C 中，我们需要的位数因平台而异——在 32 位平台（意味着内存地址是 32 位）上，我们会想要 32 位无符号整数；在 64 位平台上，我们会想要 64 位无符号整数。幸运的是，C 的设计者意识到了这种可能性，并决定为“**描述事物大小的无符号整数**”创建一个类型名——`size_t`。每当你看到 `size_t` 时，你应该想到“**具有正确位数、用于描述数组大小或索引的无符号整数**”。例如，我们的 `closestPoint` 函数如果这样写，会稍微更正确一些：

```c
point * closestPoint (point * s, size_t n, point p) {
  if (n == 0) {
    return NULL;
  }
  double bestDistance = computeDistance(s[0],p);
  point * bestChoice = &s[0];
  for (size_t i = 1; i < n ; i++) {
    double currentDistance = computeDistance(s[i],p);
    if (currentDistance < bestDistance) {
      bestChoice = &s[i];
```

“**稍微更正确**”是什么意思？实际上，它只对非常大的数组才有区别——那些大小可以用 `size_t` 表示，但不能用 `int` 表示（例如，通常超过 20 亿个元素）。这种情况不会在本书你要做的任何问题中出现，也不会在你作为新手程序员可能遇到的许多情况中出现。然而，如果你成为在一家经常处理巨大数据集的公司工作的专业程序员，它可能就重要了——养成**精确正确**的习惯那时会成为你的优势。你也会在 C 库中频繁看到 `size_t`，所以你应该知道它的含义。

既然我们在讨论数据的大小，现在正是引入 `sizeof` 运算符的好时机。回想一下，你实际上并不知道 `int` 或指针是多少字节，因为它们的实际大小因平台而异。不要写一个表示某个平台上大小的数字常量，你应该让 C 编译器用 `sizeof` 运算符为你计算类型的大小。`sizeof` 运算符接受一个操作数，它可以是一个类型名（例如 `sizeof(double)`）或一个表达式（例如 `sizeof(*p)`）。如果操作数是表达式，编译器会弄清楚该表达式的类型（记住表达式有类型），并求值该类型的大小。无论哪种情况，`sizeof` 都会求值该类型所需的字节数。这个字节数的类型是 `size_t`。
