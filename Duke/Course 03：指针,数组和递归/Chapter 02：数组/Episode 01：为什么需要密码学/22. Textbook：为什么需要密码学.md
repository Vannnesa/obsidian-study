# Cryptography Motivation
# 密码学的动机

作为一个激励性的例子，假设我们想编写一个程序来破解一个简单的密码系统，比如凯撒密码（Caesar Cipher）或维吉尼亚密码（Vigenère Cipher）。第一个是凯撒密码，以古罗马皇帝尤利乌斯·凯撒命名，它通过给每个字母加上一个固定的偏移量（例如 +3）来加密消息。例如，加密 `Hello` 会得到 `Khoor`，因为 `K` 比 `H` 后 3 个字母，`h` 比 `e` 后 3 个字母，依此类推。维吉尼亚密码应用同样的移位概念，但使用一个包含多个移位量的密钥。例如，我们可能有一个密钥 `(3,5,7,2,9)`，在这种情况下，我们会给消息的第 1、6、11、16……个字母加 3；给第 2、7、12、17……个字母加 5；等等。我们要注意，在很长一段时间里，维吉尼亚密码被认为是不可破解的，许多新手程序员在试图设计自己的加密方案时会想到它的变体。然而，它很容易被破解。

破解这两种密码都依赖于**频率统计**（frequency counting）——确定每个字母在加密消息中出现的频率——然后利用**自然语言中字母频率分布高度不均匀**这一事实。在英语中，`e` 是迄今为止最常见的字母，而 `q`、`x`、`z` 等字母则相当少见。如果我们试图破解凯撒密码，一旦我们对消息进行了频率统计，就可以猜测出现频率最高的字母是 `e`，然后尝试解密消息。如果所有字符（不仅仅是字母）都被加密，我们会猜测出现频率最高的符号是空格，并尝试解密消息。如果解密后的消息没有意义，我们可以用第二常见的字母/符号再试一次。虽然可能需要试几次，但我们通常会在第一次尝试时就成功（只要消息足够长，能给出合理的频率计数）。

如果我们真的想破解这类消息，我们会想写一个程序来做——具体来说，一个算法，它以加密消息作为输入，输出解密后的消息（如果我们担心需要多次尝试，可以让它输出最可能的几种解密消息）。编写这个程序需要几个部分。首先，我们需要对加密消息进行频率统计，然后我们需要找出哪个字母的计数最大。由于我们还不知道如何处理字符串（我们的消息会是一个字符串——而在了解数组之前，我们无法学习字符串），让我们先看看找出频率计数中最大值的问题——这里有 26 个计数，每个字母一个。你现在就可以写一个函数来实现这个算法，然而，它会**非常丑陋**：

```c
char highestFrequency(unsigned numAs, unsigned numBs, unsigned numCs, 
                      unsigned numDs, unsigned numEs, unsigned numFs, 
                      … // 省略许多参数 
                      unsigned numXs, unsigned numYs, unsigned numZs) {
  char bestLetter = 'a';
  unsigned bestCount = numAs;
  if (numBs > bestCount) {
    bestLetter = 'b';
    bestCount = numBs;
  }
```

我们草拟了这段代码，但省略了很大一部分——特别是，还有 17 个其他参数（**永远不要写一个接受 26 个参数的函数**！），以及 `e`–`y` 情况缺失的 84 行代码（另外，**永远不要写一个超过 100 行的函数**）。这种方法会奏效，但编写起来既繁琐又容易出错（当你复制/粘贴 24 个情况时，你有多可能漏改某个东西？）。如果我们处理的是 1000 个项目而不是 26 个，情况会更糟——你能想象写这个函数来找出 1000 个东西中的最大值吗？看着它，我们可以看到我们几乎在**一遍又一遍地重复同样的事情**——这表明应该有一种方法把这段代码泛化为一种算法，让程序来做重复的工作，而不是你来做。似乎必须有更好的方法，幸运的是确实有——我们可以使用**数组**！
