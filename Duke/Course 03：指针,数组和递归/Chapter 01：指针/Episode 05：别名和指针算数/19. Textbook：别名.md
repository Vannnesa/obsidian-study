# Aliasing
# 别名

在我们关于指针的讨论中，我们已经暗示了这样一个事实：我们现在可能为同一个盒子拥有多个名字；然而，我们还没有明确讨论这一点。例如，在下图中，`a` 的盒子有四个名字：`a`、`*p`、`**q` 和 `***r`。每当我们为一个盒子拥有多个名字时，我们就说这些名字**互为别名**（alias）——也就是说，我们可能会说 `*p` 是 `**q` 的别名。

![[Pasted image 20260918193510.png]]

别名在我们的编程中扮演着几个重要角色。首先，当我们在编程过程的**步骤 2** 中工作时，我们可能会发现我们改变了一个值，但有多种方式可以命名我们改变的值。当我们准确写下我们做了什么时，关键在于思考：在**步骤 1** 中手工解决问题时，我们是用哪个名字找到这个盒子的。如果我们不确定，我们应该记下我们可能使用过的其他名字——然后如果我们在泛化时遇到困难，我们可以考虑是否应该改用其他名字。

当我们在调试（或手工执行代码）时，理解别名也很重要。新手 C 程序员常常对变量在没有被直接赋值的情况下改变值感到惊讶和困惑：“我写了 `x = 4;`，然后看，我在这段代码里没有再给 `x` 赋值，但现在它是 47 了！”通常这种行为表明你给相关变量起了别名（尽管你可能不是故意的）。如果你有这类问题，在 `gdb` 中使用 `watch` 命令会非常有帮助。

如果我们想**冒险**，我们甚至可以让别名具有不同的类型。考虑以下代码：

```c
float f = 3.14;
int * p = (int *) &f;  // 通常是个坏主意！
printf("%d\n", *p);
```

这里，`f` 是 `*p` 的别名，尽管 `f` 被声明为 `float`，而 `p` 被声明为指向 `int` 的指针（所以我们告诉编译器 `*p` 是一个 `int`）。运行这段代码会发生什么？你的第一反应可能是说它打印 `3`，下面这段（类似的）代码会打印 `3`：

```c
float f = 3.14;
int x = (int) f;
printf("%d\n", x);
```

![[Pasted image 20260918193618.png]]

（图：不同类型别名的例子。将 3.14 的浮点位编码存储在 `f` 中，然后像它表示整数一样读出它。）

然而，如果我们在计算机上运行第一段代码，我们会得到 `1078523331`！这个结果可能看起来像是计算机在给我们随机的无意义内容，然而，发生的事情是完全合乎逻辑的（虽然有点底层）。当我们把 `float` 强制转换为 `int`（在第二段代码中），我们要求编译器插入从 `float` 转换为 `int` 的指令。然而，当我们解引用一个指向 `int` 的指针时，编译器只是生成指令来读取该内存位置的**位模式**，把它当作已经是 `int`。在第一段代码中，初始化 `float f = 3.14;` 把 3.14 的浮点编码的位模式写入 `f` 的盒子。不深入细节，3.14 的浮点编码结果是 `0100 0000 0100 1000 1111 0101 1100 0011`（十六进制为 `0x4048F5C3`，十进制为 `1078523331`）。当我们把指针当作 `int` 解引用时，程序读出那个位模式，像它是整数一样解释它，并打印 `1078523331` 作为输出，如上图所示。

最后一个例子不是你需要在自己编写的程序中使用的，而是对**滥用指针**的一个警告。除非/直到你确切理解这里发生了什么，并且有充分的理由这样做，否则你不应该在指针类型之间进行强制转换。
