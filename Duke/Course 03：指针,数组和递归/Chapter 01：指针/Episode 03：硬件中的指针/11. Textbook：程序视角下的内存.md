# A Program's View of Memory
# 程序视角下的内存

在 32 位机器上，地址大小为 32 位，整个内存空间从 `0x00000000` 开始（十六进制中，每个 `0` 代表 4 位 0），到 `0xFFFFFFFF` 结束（回想一下，`0x` 表示十六进制，每个 `F` 代表四个二进制 1）。每个程序都有整个地址空间可供使用，并且对于程序如何使用这个地址范围有一个约定。下图描绘了程序各个组成部分存储在内存中的位置。

## Code
## 代码

鉴于我们反复强调**一切都是数字**，程序本身可以由一系列数字来表示，这应该不会令人惊讶。生成这些数字是**编译器**的工作，它把用 C 这类语言编写的程序转换成计算机可读的一堆数字（称为**目标代码**，object code）。例如，C 中一条把两个数字相加的指令，可能被编码为目标代码中的一条 32 位指令。这 32 位中的一些会告诉机器执行加法，一些位会编码要相加哪两个数字，还有一些位会告诉处理器应该把计算出的和存储在哪里。编译器把 C 代码转换成目标代码，并为每条编码后的指令分配一个内存位置。这些编码后的程序指令位于内存的 **Code**（代码）部分，在上图中用黄色显示。

## Static Data
## 静态数据

**静态数据区**包含在整个程序运行期间都可访问的变量（例如**全局变量**）。与在函数内部声明、函数返回后就不再可访问的变量不同，静态变量在整个程序终止之前都可访问（因此称为 **static**，静态）。从概念上讲，静态变量的“盒子”在整个程序中都“留在图中”，而其他变量只在程序生命周期的一部分内可用。这些变量被放在它们自己的内存位置中，紧挨着程序的代码部分之后，如上图所示。

内存的最后两个部分用于两种不同类型的程序数据，它们在程序执行期间的特定时间可用。**堆**（Heap，紫色）存储**动态分配**的数据。**栈**（Stack，橙色）存储每个函数声明的**局部变量**。栈被划分为**栈帧**（stack frames），栈帧从函数被调用时开始可用，一直持续到它返回。本书中的概念图主要把栈帧画成盒子（每个函数一个），其中包含局部变量。实际上，栈是一段连续的内存；每个栈帧位于调用它的函数的栈帧下方。

有了这些关于指针如何工作以及代码如何放置在内存中的细节，我们可以更详细地展示 `swap` 函数执行期间发生的事情。下一个视频展示了同一个 `swap` 函数的执行，但使用连续的栈视图和作为指针值的内存地址。它还把程序代码以 4 字节盒子存储在内存中。栈的**返回地址**字段——之前在我们的概念图中被描绘为蓝色的调用点位置——在这个视频中也变得明确。**返回地址**是被调用函数完成并返回后，下一条应该执行的指令的地址。

**调用约定**（calling convention）——即参数如何传递给函数、值如何从函数返回的具体细节——类似于 x86 机器；函数的参数位于调用它的函数的栈帧中。这与我们之前展示的概念图略有不同，在那些图中，参数被放在被调用函数的栈帧中。对于概念图来说，这既足够又容易理解。硬件细节对于每种目标体系结构都会略有不同。
