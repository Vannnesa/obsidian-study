# NULL

在下图中，代码段下方有一块空白区域，它是程序内存中的一个**无效区域**。你可能会想，为什么代码不从地址 0 开始，而不是浪费这块空间。原因是程序使用数值为 0 的指针——它有一个特殊的名字 **NULL**，表示“**不指向任何东西**”。通过不让程序的任何有效部分放在地址 0（或附近），我们可以确保没有任何东西会被放在地址 0。这意味着，任何正确初始化、确实指向某物的指针，都**永远不会**具有值 `NULL`。

知道一个指针不指向实际的东西，在很多情况下都很有用。其一，我们有时会有算法需要回答“**没有答案**”。例如，如果我们思考之前讨论过的最近点例子，当点集为空时，我们必须返回“没有答案”——使用指针，我们可以返回一个指向点的指针，并在“没有答案”的情况下返回 `NULL`。我们也可能有负责创建某物的函数，如果创建失败则返回 `NULL`——我们将会看到打开文件（以便从磁盘读取数据）的函数会以这种方式失败。课程后面我们将看到如何**动态分配内存**，如果内存无法分配，也会返回 `NULL`。我们还将开始学习**链式结构**（linked structures），它们用指针从一个项存储到下一个项，并使用 `NULL` 表示序列的结束。

当我们使用 `NULL` 时，我们会把它表示为一个**平头箭头**（表示它不指向任何东西），如下图所示。每当我们有 `NULL` 时，我们可以使用指针本身（它的数值就是 0），然而，我们**不能沿着箭头走**（因为它不指向任何东西）。如果我们试图沿着箭头走（即**解引用**该指针），那么我们的程序会因**段错误**（segmentation fault）而崩溃——这是一个错误，表明我们试图以无效方式访问内存（事实上，如果你的程序试图访问上图中任何“空白”的内存区域，它都会因段错误而崩溃）。

`NULL` 指针有一个我们还没见过的特殊类型——`void *`。**void 指针**表示指向任意类型的指针，并且与任何其他指针类型兼容——我们可以把它赋给 `int *`、`double *`，或任何我们想要的其他指针类型。同样，如果我们有一个 `void *` 类型的变量，我们可以把任何其他指针类型赋给它。因为我们不知道 `void *` 实际指向什么，所以我们既不能**解引用**它（编译器不知道它应该在箭头末端找到什么类型的东西），也不能对它进行**指针算术**。
