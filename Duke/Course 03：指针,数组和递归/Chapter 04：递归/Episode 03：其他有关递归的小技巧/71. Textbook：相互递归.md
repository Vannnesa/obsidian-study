# Mutual Recursion
# 相互递归

我们可能也会发现，用**相互递归**（mutual recursion）来编写一些函数很有用——即两个或多个函数互相调用。回想一下，当我们的泛化步骤要求我们在更接近**基准情况**（base case）的参数值上解决同一个问题时，就会出现递归函数。当我们编写一个函数，发现一个想要抽象到第二个函数中的复杂步骤，然后去编写那个第二个函数时，却发现它也有一个复杂步骤恰好与第一个函数匹配，这时就会出现**相互递归函数**。这里，我们同样需要小心，确保这对相互递归的函数朝着**不需要递归的基准情况**推进——否则，我们会无限递归，程序将无法终止。

作为一个（有点刻意设计的）例子，假设我们没有取模（`%`）运算符，想要编写一个函数来判断一个正数是否为偶数。我们可能从这样的事实出发：`0`（是偶数）和 `1`（不是偶数）是简单情况（严格来说，我们只需要一个基准情况：`0`），并利用“`n` 是偶数当且仅当 `n - 1` 是奇数”这一事实。这样的推理会引导我们写出以下代码：

```c
int isEven (unsigned int n) {
	if (n == 0) {
	  return 1;
  }
  if (n == 1) {
    return 0;
  }
  return isOdd (n - 1); // 复杂步骤：抽象成一个函数
}
```

我们现在需要接着编写 `isEven` 实现中所依赖的 `isOdd` 函数。在编写它时，我们可能从这样的事实出发：`0`（不是奇数）和 `1`（是奇数）是简单情况，并利用“`n` 是奇数当且仅当 `n - 1` 是偶数”这一事实。然后我们会写：

```c
int isOdd (unsigned int n) {
  if (n == 0) {
	  return 0;
  }
  if (n == 1) {
    return 1;
  }
  return isEven (n - 1); // 已经有函数来做这一步
}
```

这两个函数是**相互递归**的——它们互相调用。注意，我们需要在第一个函数之前编写第二个函数的**原型**（回想一下，函数原型告诉编译器名称、返回类型和参数类型，但不提供函数体），以便让编译器知道第二个函数的存在。生成的代码会像这样：

```c
int isOdd (unsigned int n); // isOdd 的原型
int isEven (unsigned int n) {
  if (n == 0) {
    return 1;
  }
  if (n == 1) {
    return 0;
  }
  return isOdd (n - 1); // 复杂步骤：抽象成一个函数
}
```

虽然这个偶数/奇数的例子相当刻意（如果你想知道一个数是奇数还是偶数，直接测试 `n % 2 == 0` 是否成立要高效得多），但相互递归函数有许多重要用途。一个常见用途是**递归下降解析**（recursive descent parsing）。**解析**是分析输入文本以确定其含义的过程。递归下降解析器通常通过编写许多函数（每个函数解析输入的特定部分）来实现，这些函数然后相互递归来完成它们的工作。我们这里不深入细节，但你可以通过思考 C 函数及其参数来想象这种相互递归的性质——例如，如果你正在为 C 编译器编写解析器。

在高层次上，要解析一个函数调用（`f(arg1, arg2,...)`），你会编写一个函数 `parseCall`。`parseCall` 会读取函数名和左括号，然后反复调用另一个函数 `parseExpression` 来解析每个参数（参数必须是表达式）——同时检查参数后面是逗号还是右括号。`parseExpression` 函数本身可能遇到函数调用，在这种情况下，它需要调用 `parseCall`。如果被解析的文本看起来像 `f(3,g(42), h(x,y,z(1)))`，就会出现这种情况——`f` 的一些参数本身就是函数调用，事实上，`h` 的一个参数也是函数调用。

这样的解析通常会导致一个**相互递归定义的数据结构**——意味着你有两个（或更多）类型互相递归引用。操作相互递归数据结构的算法通常很自然地适合用相互递归实现。当然，相互递归数据结构也可能出现在各种其他上下文中。
