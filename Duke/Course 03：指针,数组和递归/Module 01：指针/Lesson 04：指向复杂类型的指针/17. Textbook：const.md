# const

在我们讨论指向各种类型的指针时，现在正是引入 **const 数据**概念的好时机——即我们告诉编译器不允许修改的数据。当我们声明一个变量时，可以在其类型中添加 `const`，以指定编译器不应允许我们修改该数据：

```c
const int x = 3; // 给 x 赋值是非法的
```

如果我们试图改变 `x` 的值，编译器会产生错误。将数据声明为 `const` 很有用，因为它消除了我们程序中某一类错误：修改我们不应修改的东西。

当我们有指针时，有两样不同的东西可以是 `const`：**指针所指向的数据**（箭头末端盒子中的内容），或**指针本身**（它指向哪里）。如果我们写：

```c
const int * p = &x;
```

我们把 `p` 声明为指向 `const int` 的指针——也就是说，`p` 指向一个 `int`，而我们不允许修改那个 `int`。我们可以改变 `p` 指向的位置（例如，`p = &y;` 是合法的——如果 `y` 是 `int`）。然而，改变 `p` 所指向盒子中的值（例如 `*p = 4;`）是非法的——我们已经说过 `p` 指向的 `int` 是 `const`。如果我们确实尝试写类似 `*p = 4;` 的代码，我们会得到这样的编译器错误：

```text
assignment of read-only location '*p'
```

我们可以通过写成下面这样达到完全相同的效果：

```c
int const * p = &x; // 与 const int * p 相同
```

如果我们想指定我们可以改变 `*p`，但不能改变 `p` 本身，我们会写：

```c
int * const p = &x;
```

这个声明表示 `p` 是一个指向（可修改的）`int` 的 `const` 指针。写 `*p=4;` 是合法的，但写 `p =&y;` 是非法的。如果我们愿意，可以结合两者，既防止改变指针指向的位置，也防止改变它指向的值：

```c
const int * const p = &x;
```

同样的原则适用于指向指针的指针（指向指针的指针的指针……）。例如，对于一个 `int **`，我们有以下组合：

| 声明 | 能改变 `**p` 吗？ | 能改变 `*p` 吗？ | 能改变 `p` 吗？ |
|---|---|---|---|
| `int ** p` | 是 | 是 | 是 |
| `const int ** p` | 否 | 是 | 是 |
| `int * const * p` | 是 | 否 | 是 |
| `int ** const p` | 是 | 是 | 否 |
| `const int * const * p` | 否 | 否 | 是 |
| `const int ** const p` | 否 | 是 | 否 |
| `int * const * const p` | 是 | 否 | 否 |
| `const int * const * const p` | 否 | 否 | 否 |

注意，`const` 的声明只是告诉编译器：只有当我们试图**通过**声明为 `const` 的变量改变数据，或执行某种会丢弃 `const` 性质的操作时，才给我们错误。例如，下面是合法的：

```c
int x = 3;
const int * p = &x;
x = 4;
```

这里，我们不允许改变 `*p`，然而，我们在 `*p` 处找到的值仍然可以通过给 `x` 赋值来改变（因为 `x` 不是 `const`，给它赋值不是错误）。然而，如果我们写：

```c
const int y = 3;
int * q = &y;
*q = 4;
```

那么我们将会收到一个编译器警告（我们应该把它当作错误处理）：

```text
initialization discards 'const' qualifier from pointer target type [enabled by default]
```

错误在第 2 行，我们把 `&y`（类型为 `const int *`）赋给 `q`（类型为 `int *`）——丢弃了 `const` 限定符（`const` 被称为**限定符**，因为它修饰一个类型）。这段代码是错误的原因是，第 3 行的 `*q=4;` 将会完全合法（`q` 所指向的类型没有用 `const` 限定符声明），但会做一件我们已经明确说过不想做的事情：修改 `y` 的值。

新手程序员常常对第一个例子合法而第二个不合法感到困惑——在两个例子中，我们都试图声明一个变量和一个指向该变量的指针，一个带 `const`，另一个不带。然后我们试图通过那个不带 `const` 的来修改盒子中的值——但一个没问题，另一个不行。这些规则实际上是有道理的：在第二个情况中，我们说了“`y` 不能被修改”，然后我们试图说“`q` 是一个指针（我可以用它来修改或读取值），指向 `y`”——这明显违反了我们关于“`y`”所说的（它不能被修改）。然而，在第一个情况中，我们在说“`x` 是一个可以被修改的变量”，然后说“`p` 是一个指针，我们只能用读取它指向的值，不能修改它”——这没有对“`x`”施加新限制（也没有违反现有限制），只是告诉我们能用“`p`”做什么、不能做什么。
