# Preprocessing
# 预处理

第一步位于左上角，是**预处理器**（preprocessor），它接收你的 C 源文件，并将其与所包含的任何**头文件**（header files）合并，同时展开你可能使用的任何**宏**（macros）。为了帮助理解这个过程，我们来看第一个完整的 C 程序。它在算法上很简单（它所做的只是打印 Hello World），但有助于解释编译过程。

```c
#include <stdio.h>
#include <stdlib.h>

int main (void) {
  printf ("Hello World\n");
  return EXIT_SUCCESS;
}
```

虽然 `main` 函数的内容应该大部分都很熟悉——调用 `printf`，以及一个 `return` 语句——但这个程序中有几个新概念。前两行是 **include 指令**。这些代码行实际上并不是程序运行时执行的语句，而是给编译器**预处理器**部分的指令。具体来说，这些指令告诉预处理器在程序源代码中的那个位置**原样包含**指定文件的内容，然后再将其传递给编译过程的后续步骤。

## Header Files
## 头文件

这些 `#include` 指令将要包含的文件名放在尖括号 `<>` 中，因为该文件是标准 C **头文件**之一。如果你编写自己的头文件，你会通过将文件名放在引号中来包含它（例如 `#include "myHeader.h"`）。（这不是正式规则，而是非常常见的约定。）预处理器指令以井号 `#` 开头，并有自己的语法。

在这个特定程序中，有两个 include 指令。第一个指示预处理器包含文件 `stdio.h`，第二个指示它包含 `stdlib.h`。这些头文件——以及一般的头文件——主要包含三样东西：**函数原型**（function prototypes）、**宏定义**（macro definitions）和**类型声明**（type declarations）。

**函数原型**看起来很像函数定义，只是用分号代替了函数体。原型告诉编译器该函数存在于程序的某个地方，以及该函数的返回类型和参数类型。提供原型允许编译器检查传递给函数的参数数量和类型是否正确，以及返回值是否被正确使用，而无需提供完整的函数定义。对于 `printf`，`stdio.h` 提供了原型。`printf` 的实际实现位于 **C 标准库**内部，我们将在后面学习**链接器**（linker）时进一步讨论。

## Macros
## 宏

头文件也可能包含**宏定义**。宏定义最简单的用途是定义一个常量，例如：

```c
#define EXIT_SUCCESS 0
```

这个指令（来自 `stdlib.h`）告诉预处理器将符号 `EXIT_SUCCESS` 定义为 `0`。每当预处理器遇到符号 `EXIT_SUCCESS` 时，它会看到它被定义为宏，并将该宏展开为其定义。在这个例子中，定义就是 `0`，所以预处理器在传递给后续编译阶段的源代码中把 `EXIT_SUCCESS` 替换为 `0`。注意，预处理器将输入拆分为**标识符**，并检查每个标识符是否是已定义的宏，所以 `EXIT_SUCCESS_42` **不会**展开为 `0_42`，而是不会被认为是宏，预处理器会保留它不动（除非它在其他地方被定义）。

使用宏定义来表示常量，比直接写数字常量给程序员提供了多种优势。
其一，如果程序员需要更改常量，只需更改宏定义，而不是常量被使用的所有地方。
另一个优势是，给常量命名使代码更具**可读性**。在 `return EXIT_SUCCESS` 中给常量命名，给了你一个线索：这里的返回值表示程序**成功**。事实上，这正是这个语句所做的。`main` 的返回值向运行你程序的任何程序表明你的程序是成功还是失败。

使用宏定义常量的第三个优势是**可移植性**（portability）。虽然 `0` 在你的平台（你所拥有的硬件类型和操作系统的组合）上可能表示成功，但在某些其他平台上它可能表示失败。如果你把常量 `0` 硬编码到代码中，那么它在你的平台上可能是正确的，但在另一个平台上可能需要重写才能正确工作。相比之下，如果你使用标准头文件中定义的常量，那么当你在新平台上重新编译程序时，它就会正确工作——该平台上的头文件会将这些常量定义为正确的值。

你将在编写并运行一个简单的 “Hello World” 程序之后，进一步学习更多关于宏的知识。
