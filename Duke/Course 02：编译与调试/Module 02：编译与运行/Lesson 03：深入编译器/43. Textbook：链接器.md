# Linking
# 链接

这个过程的最后一步是**链接**程序。链接程序会接受一个或多个**目标文件**，将它们与各种**库**以及一些**启动代码**组合在一起，并生成实际的**可执行二进制文件**。目标文件通过**名称**引用函数，链接器的工作就是解析这些引用——找到匹配的**定义**。如果链接器找不到所使用的某个名称（称为“**符号**”，symbol）的定义，或者同一个符号被定义了多次，它就会报告错误。

链接器错误——由 `ld`（链接器的名字）报告——通常比其他编译器错误少见。如果你遇到**未解析符号**错误，这意味着你要么没有定义该符号，要么没有在链接中包含定义该符号的目标文件，要么该符号被指定为仅在该目标文件内部可见（这可以通过使用 `static` 关键字来实现——这是一个我们不会深入探讨的特性）。如果你遇到符号**重复定义**的错误，首先确保你没有试图用同一个名字命名两个不同的函数。接下来，确保你没有在编译命令行中两次包含任何文件。最后，确保你没有 `#include` 一个 `.c` 文件——只应包含头文件——并且你只在头文件中包含函数**原型**，而不是函数的**定义**（这些规则有一些高级例外，但如果你到了那个阶段，你应该对链接过程和 `static` 关键字有足够的理解来修复任何问题）。

有时你可能希望使用**外部库**——一组已经编写好并打包起来用于某种目的的函数（例如，绘制图形、播放声音、高级数学，或许多其他目的）。C 库就是这样一个例子，它默认被链接进来。对于其他库，你必须用 `-l` 命令行选项明确请求链接器与库链接，并在 `l` 后面紧跟库的名称。

如果一切顺利，链接器将解析所有符号引用，并将各个目标文件和库组合成一个**可执行二进制文件**。
