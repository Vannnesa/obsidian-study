# Assembling
# 汇编

下一步是获取编译器生成的**汇编代码**，并将其**汇编**成一个**目标文件**（object file）。`gcc` 调用**汇编器**（assembler），将汇编指令从文本/人类可读格式翻译成处理器能够理解和执行的**数值编码**。这种翻译是“**一切都是数字**”规则的另一个例子——甚至计算机执行的指令也是数字。

虽然在这个阶段有可能出现错误消息，但对于你在本专项课程中尝试做的任何事情，都不应该发生这种情况。一般来说，这里的错误仅限于你明确将自己想要的特定汇编级指令写进程序（这在 C 中是可能的，但仅限于非常高级的情况）并在这些指令中犯错的情况。

关于这一步，需要理解的重要一点是：它会产生一个**目标文件**。目标文件包含你所编译源文件的机器可执行指令，但**还不是一个完整的程序**。目标文件可能引用它没有定义的函数（例如 C 库中的函数，或其他文件中编写的函数）。你可以通过指定 `-c` 选项，要求 `gcc` 在汇编出目标文件后**停止**。默认情况下，目标文件的名称将是 `.c` 文件名把 `.c` 替换为 `.o`。例如，`gcc -c xyz.c` 会把 `xyz.c` 编译成 `xyz.o`。如果你希望为目标文件提供不同的名称，使用 `-o` 选项，后面跟上你想要的名字。例如，`gcc -c xyz.c -o awesomeName.o` 会生成一个名为 `awesomeName.o` 的目标文件。

这种**停止的能力**对于大型程序很重要，在大型程序中你会把代码拆分到多个不同的 C 文件里。把程序拆分成较大的文件，主要有助于让你把代码分成**可管理的片段**。然而，每个源文件都可以单独编译成一个目标文件，然后这些目标文件可以**链接**在一起（我们将在下一节讨论）。如果你更改了某个文件中的代码，你可以只重新编译那个文件（为它生成新的目标文件），并重新链接程序，而无需重新编译任何其他源文件。对于你在本专项课程中编写的程序，这不会有什么差别。然而，当你编写真实程序时，你可能有数万或数十万行代码，拆分在几十或几百个文件中。在这种情况下，重新编译一个文件和重新编译所有文件（特别是如果启用了优化）之间的差别，可能是**几十秒和几十分钟**之间的差别。
