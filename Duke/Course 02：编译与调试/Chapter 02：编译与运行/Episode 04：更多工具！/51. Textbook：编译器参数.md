# Compiler Options
# 编译器参数

通常，你会希望把生成的可执行程序命名为有意义的名字，而不是默认的 `a.out`。要更改输出文件名，使用 `-o` 选项，并在其后指定输出文件名。例如，`gcc -o myProgram myProgram.c` 会编译 `myProgram.c`（同上），但不会生成 `a.out`，而是把程序命名为 `myProgram`。

另一个你通常会想使用的选项是 `--std=gnu99`。这个选项指定编译器应使用带 GNU 扩展的 **C99 标准**。实际上 C 有几个不同版本（称为“**标准**”，因为它们反映了特性的标准化）。`gnu99` 会与本课程描述的内容匹配，并且通常是一个合理的编程标准。

另一对有用的选项是 `-Wall` 和 `-Werror`。第一个请求编译器对**广泛范围的可疑行为**发出**警告**。正如我们之前讨论的，编译器会检查程序中的某些错误。如果检测到错误，它会向你报告，并要求你在继续之前修复它们。警告与错误类似，编译器会报告它检测到的问题；然而，与错误不同的是，即使编译器警告了你某些事情，它仍会继续并生成程序。`-Werror` 选项告诉编译器**把所有警告当作错误**——使得在程序员修复所有警告之前，编译器拒绝编译程序。

新手程序员常常想知道，为什么一开始要启用警告，尤其是要求编译器把警告转换为错误。错误会阻止程序编译，所以似乎任何避免错误并得到编译后二进制文件的方法都是好事。然而，程序员的目标不仅仅是生成任何可执行程序，而是生成一个**能正确工作**的程序。任何时候编译器能提醒你潜在问题，你修复它们都比它们导致问题后你必须调试要容易得多。一个很好的类比是买房子。把编译器想象成你的房屋检查员。虽然你急于购买并搬进新房子，但你更愿意让检查员在你买房子并搬进去之前发现潜在问题。

我们强烈建议至少使用以下警告选项进行编译：

```compiler_option
-Wall -Wsign-compare -Wwrite-strings -Wtype-limits -Werror
```

这些选项将帮助捕获许多错误，并且不应对正确编写的代码造成不适当的负担。

较新版本的 `gcc` 还支持选项 `-fsanitize=address`，它会生成包含额外检查的代码，以帮助在**运行时**检测各种问题。在你的开发周期中，也强烈建议使用这个选项。然而，我们要注意（至少对于 `gcc 4.8.2` 和 `valgrind 3.10.0`），你不能在 `valgrind` 中运行用这个选项构建的程序。这两个工具检测的问题集不同但有重叠，所以两者都用是个好主意——只是必须**分开使用**。
