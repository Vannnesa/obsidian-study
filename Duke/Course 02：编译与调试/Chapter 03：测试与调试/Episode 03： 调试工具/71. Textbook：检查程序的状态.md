# Investigating the State of Your Program
# 检查程序的状态

调试器最有用的功能之一，是能够**检查程序的状态**。我们目前讨论的 `print` 和 `display` 命令提供了一个起点，因为它们让你看到表达式求值的结果，然而，你还可以做更多事情。

一个有用的功能是能够检查当前的**栈帧**（stack frames）集合，并在其中上下移动。`backtrace` 命令列出所有栈帧（当前帧在最上面，`main` 在最下面），这样你可以看到哪些函数调用把你带到了当前位置。`backtrace` 还列出每个调用发生的行号（或者对于当前帧，列出执行箭头所在的行）。

当你打印表达式时，`gdb` 使用**当前作用域**中的变量。然而，有时你可能想检查栈中更上层其他帧中的变量。你可以用 `up` 和 `down` 指示 `gdb` 选择不同的帧，它们专门在栈中上下移动。

`up` 的一个特别常见用途是当程序在失败的 `assert` 处停止时。发生这种情况时，`gdb` 会停在 C 库深处处理 `assert` 的代码中。然而，你会想回到你自己的代码，它在上面几个栈帧处。你可以使用几次 `up`，直到 `gdb` 返回到对应于你代码的帧。

你还可以用 `info` 命令获取程序各个方面的信息，它有各种子命令。例如，`info frame` 会描述当前帧的内存布局，`info types` 会描述当前程序中的类型。有各种各样的 `info` 命令，但大多数用于更高级的用途——你可以使用 `help info` 查看所有命令。
