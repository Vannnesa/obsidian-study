# Controlling Execution
# 控制执行

`next` 和 `step` 命令给了你推进程序状态的基本能力，然而，还有更高级的命令用于控制执行。如果我们在调试一个大型、复杂的程序，我们可能不想逐行步进到程序中我们想要收集信息的那个点。

控制程序执行最有用的方法之一是在特定行上设置**断点**（breakpoint）。断点指示 `gdb` 在程序到达该特定行时停止执行。你可以用 `break` 命令设置断点，后面跟上行号或函数名（表示在该函数的开头设置断点）。在 `emacs` 中，你也可以按 `C-x space` 在当前位置设置断点。也可以在特定内存地址设置断点，尽管那是更高级的功能。当我们设置断点时，`gdb` 会给它分配一个编号，我们可以用这个编号在其他与断点相关的命令中识别它。

一旦我们设置了一个断点，就可以运行程序（或者如果它已经启动，就使用 `continue`），它会一直执行，直到遇到断点（或某些其他导致执行停止的条件）。当遇到断点时，`gdb` 会在 `(gdb)` 提示符处把控制权交还给我们，允许我们给它其他命令——我们可能会检查程序状态、设置更多断点，然后继续。

默认情况下，断点是**无条件断点**——`gdb` 会在程序任何时候到达相应行时停止程序并交给你控制权。然而，有时我们可能希望在特定条件下停止。例如，我们可能有一个执行 1,000,000 次的 `for` 循环，而我们需要 `i` 为 250,000 的那次迭代中的信息。使用无条件断点，程序会停止，我们需要继续很多次才能得到想要的信息。相反，我们可以使用**条件断点**——我们给 `gdb` 一个 C 表达式来求值，以决定它是否应该交给我们控制权，还是让程序继续运行。

我们可以在用 `break` 命令创建断点时，通过在位置后面写 `if`，再跟上条件表达式，来给断点加上条件。我们也可以稍后用 `cond` 命令添加条件（或更改已有条件）。例如，如果我们想在 `size` 行上设置一个条件为 `i==25000` 的断点，我们可以告诉 `gdb`：

```text
(gdb) break 7 if i==250000
```

或者，如果断点已经存在，例如作为断点 1，我们可以写：

```text
cond 1 i==250000
```

如果我们写一个不带表达式的 `cond` 命令，那么它会使断点变为无条件。我们也可以（通过它们的数字 id）**启用**或**禁用**断点。被禁用的断点仍然存在（并且以后可以重新启用），但没有效果——它不会导致程序停止。我们也可以通过数字 id 删除断点。你可以使用 `info breakpoints` 命令（可以缩写为 `i b`）查看当前断点的状态。

另外两个控制程序执行的有用命令是 `until`，它使循环执行直到结束（`gdb` 停在循环之后的第一行），以及 `finish`（可以缩写为 `fin`），它结束当前函数——也就是说，执行直到当前函数返回。
