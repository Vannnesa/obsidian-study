# Getting Started with gdb
# gdb 入门

使用 `gdb`（或大多数其他调试工具）的第一步是**在编译代码时包含调试符号**（debugging symbols）——这些额外信息帮助调试工具理解代码和数据在内存中的布局。`gcc` 的 `-g` 选项请求包含这些调试信息，但如果你特别使用 `gdb`，你应该使用 `-ggdb3`，它以 `gdb` 专用格式请求最大量的调试信息（例如，它会包含预处理器宏定义的信息）。注意，如果你分多步编译程序（先生成目标文件，再链接），你应该在**所有步骤**中都包含 `-ggdb3`。

一旦你用调试符号编译好程序，就需要运行 `gdb`。你可以直接从命令行运行 `gdb`，然而，**在 `emacs` 内部运行它要好得多**。要在 `emacs` 中运行 `gdb`，使用命令 `M-x gdb`（即根据你的键盘设置，按 `ESC x` 或 `ALT-x`，然后输入 `gdb`，按回车）。此时，`emacs` 应该提示你希望如何运行 `gdb`（“Run gdb (like this):”），并提供一个建议的命令行。通常 `emacs` 建议的选项就是你要的；不过，你可能想更改要调试的程序名称（指定为命令行的最后一个参数）。一旦你对命令行满意，按回车启动 `gdb`。

此时，你会得到一个标题为 `*gdb*` 或 `*gdb-prog*`（其中 `prog` 是程序名）的缓冲区。缓冲区名称中的星号表示该缓冲区对应与**进程**的交互，而不是磁盘上的文件。这个缓冲区应该包含 `gdb` 的一些输出，告诉你它的版本、在哪里找到手册的信息，以及关于 `help` 命令的消息。输出的最后几行应该是（把 `yourProgram` 替换为你正在调试的程序名）：

```text
Reading symbols from yourProgram...done.
(gdb)
```

注意，如果你反而得到以下内容，说明你没有用调试符号编译（在这种情况下，你应该用调试符号重新编译）：

```text
Reading symbols from yourProgram...(no debugging symbols found)...done.
(gdb)
```

另外，这条消息表明你请求的程序在当前目录中不存在：

```text
yourProgram: No such file or directory.
(gdb)
```

注意，输出最后一行开头的 `(gdb)` 是 `gdb` 的**命令提示符**。每当它显示这个提示符时，它就准备好接受你的命令。我们将要学习的第一个命令是：

- `start`：开始（或重新开始）程序的执行。一旦执行进入 `main`，就停止程序（以接受更多命令）。

- `run`：这个命令运行程序（可能重新启动它）。除非遇到其他导致它停止的条件（我们稍后会学习这些），否则它不会停止。

- `step`：将程序推进一个“步”，很像我们手工执行代码时推进执行箭头。更具体地说，`gdb` 会一直执行，直到执行箭头移动到源代码的不同行，无论是通过转到下一行、因控制流而跳转，还是其他原因。特别地，`step` 会**进入**当前行调用的函数。这个命令可以缩写为 `s`。

- `next`：将程序推进一行代码。然而，与 `step` 不同，如果当前代码行是函数调用，`gdb` 会执行整个被调用的函数而不停止。这个命令可以缩写为 `n`。

- `print`：`print` 命令接受一个表达式作为参数，求值该表达式，并打印结果。注意，如果表达式有**副作用**，它们会发生，并影响程序的状态（例如，如果你执行 `print x = 3`，它会把 `x` 设为 `3`，然后打印 `3`）。你可以在 `print` 后面加上 `/x`，以十六进制格式打印结果。这个命令可以缩写为 `p`（或 `p/x` 以十六进制打印）。每次你打印一个表达式的值时，`gdb` 会把该值记住在它自己的内部变量中，这些变量名为 `$1`、`$2` 等（你可以看出它用了哪一个，因为它在打印值时会说明赋值给了哪一个——例如 `$1 = 42`）。如果你想在以后使用这些值，可以在其他表达式中使用这些 `$` 变量。`gdb` 还有一个功能，让你打印数组中的多个元素——如果你在一个左值后面加上 `@number`，`gdb` 会从你命名的位置开始打印 `number` 个值。这个功能对数组最有用——例如，如果 `a` 是一个数组，你可以执行 `p a[0]@5` 来打印 `a` 的前 5 个元素。

- `display`：`display` 命令接受一个表达式作为参数，并在每次 `gdb` 停止并显示提示符时显示它的值。例如，`display i` 会在每个 `(gdb)` 提示符之前求值并打印 `i`。你可以把这个命令缩写为 `disp`。

如果你不输入任何命令直接按回车，`gdb` 会**重复你输入的最后一个命令**。当你想连续多次使用 `step` 或 `next` 时，这个功能最有用。

注意，如果你需要向程序传递命令行参数，你可以在 `start` 或 `run` 命令后面写它们（例如 `run someArg anotherArg`），或者你可以使用 `set args` 来设置命令行参数。
