# 步骤 7：调试

一旦你在代码中发现了问题，就需要修复它——这个过程称为**调试**（debugging）。许多新手程序员（甚至一些有一定经验的程序员）以**临时凑合**的方式调试——试图在代码中改点什么，并希望这能解决问题。这种方法很少有效，而且常常导致很多挫败。

回到我们之前的医生类比，假设你生病了去看医生。你的医生会说“哦，我不知道哪里出了问题，但试试这个药。如果没治好，明天再来，我们试试另一种药……”吗？如果你的医生这样对待你，也许是时候换个医生了！尝试随机的“修复”，希望碰巧有一个奏效，不是诊断和修复问题的好方法。更糟的是，如果在这个过程中你的症状发生变化，你根本不知道是你尝试的某个随机“修复”让情况变糟了，还是你未治疗的病情在恶化。类似的类比可以用于任何诊断和修复问题的职业（例如机械师）。
