# This reading is a reference for resolving a variety of common problems with git and grade
# 本文是解决 git 和 grade 各种常见问题的参考

这篇阅读材料是解决 `git` 和 `grade` 各种常见问题的参考。当然，欢迎你现在阅读，但我们主要建议你在遇到这些问题之一时再回来查阅。请不要觉得你必须吸收本文档中的所有信息才能继续。其中一些问题（尤其是末尾的问题）是其他学习者遇到过的有些罕见和奇怪的问题——希望你永远不会遇到其中大部分问题！

## Git status is not clean (untracked files)
## Git 状态不干净（未跟踪文件）

当你收到这个错误消息时，意味着你有**未放入 git 的文件**。`grade` 命令不希望在这种情况下评分，因为看起来你可能没有提交所有工作（而且只根据部分文件得到成绩会让人烦恼/困惑）。如何修复取决于你想对每个文件做什么：

如果你想**提交该文件**，那么需要把它加入 git。例如，要提交 `hello.txt`，你会执行：

```bash
git add hello.txt
```

如果你想**删除该文件**，那么用 `rm` 命令删除它。注意，如果你删除文件，它将**永远消失且无法恢复**，因为它不在 git 中。例如，如果你想删除 `#hello.txt#`，你会执行：

```bash
rm \#hello.txt#
```

注意，因为这个文件名以 `#` 号开头（命令 shell 会特殊解释它），你需要写 `\#` 而不是 `#`。还要注意，这个命令**不是** `git rm`，因为该文件不在 git 中。你只是在删除文件。

做完这些后，你需要执行 `git commit` 提交更改，然后 `git push` 把提交发送到评分器能找到的地方。之后你就可以执行 `grade` 了。

## Git status is not clean (deleted files)
## Git 状态不干净（已删除文件）

如果你用 `rm`（而不是 `git rm`）删除了一个 git 正在跟踪的文件，那么 git 会将该文件列为已删除但未暂存提交。例如：

（图）

同样，你在这里做什么取决于你想要的结果：

- **如果你有意删除该文件并且不再需要它**：那么你只需要用 `git rm filename` 告诉 git 你想删除它（然后提交）。例如，如果文件是 `code1.c~`，你会执行：

```bash
git rm code1.c~
git commit -m "removed backup file"
```

- **如果你不是有意删除该文件，想要它回来**：那么你可以用 `git checkout filename` 恢复最近提交的版本。例如，如果文件是 `code1.c`，你会执行：

```bash
git checkout code1.c
```

如果你需要恢复的不是最新版本，请参见下一节。

## I deleted or messed up a file I need
## 我删除或弄坏了一个我需要的文件

假设你不小心删除了一个 `README` 文件。例如，这里我不小心删除了 `01_apple` 的 `README`。当我执行 `ls` 时，看不到任何文件。

（图）

如果你刚刚删除了一个已提交到 git 的文件，那么你可以用以下命令恢复它：

```bash
git checkout README
```

这会从 git 恢复最近提交的版本。

如果你把一个弄坏的版本提交到了 git，那么你需要多做一些工作来恢复之前的提交。第一步是找到你想要的那一个正确的过去版本。你可以用 `git log` 命令完成。例如，如果我们试图把 `README` 恢复到过去的某个版本：

```bash
git log README
```

会显示 `README` 的提交历史。注意，它会显示你提交时写的日志消息（无论是用 `-m "message"` 还是在 `emacs` 中写的）。**写好日志消息可以帮助你找到要恢复哪个版本！**

（图）

在这个例子中，我们有 3 个可能的过去版本可以恢复。最上面的是最近的提交，也就是我们用 `git checkout README` 会恢复的版本。然而，假设我们想恢复评分系统发布的那个版本。这是最旧的版本，位于最下面（它还显示作者是 `Learn 2 Program Grader`，意味着它来自评分系统而不是 `Coursera Learner`，后者意味着来自你）。你需要获取**提交 ID**，也就是黄色显示的长十六进制数字，在这个例子中是 `177ca343cb13e6bc618edc8950d71e1ab70ba568`（直接复制粘贴它！不要自己重新输入）。然后你可以执行：

```bash
git checkout 177ca343cb13e6bc618edc8950d71e1ab70ba568 README
```

来恢复该版本的文件。

## I ran grade, but do not see the next assignment!
## 我运行了 grade，但看不到下一个作业！

如果你评分了一个作业但看不到下一个，你应该做以下事情：

1. `git pull`：确保所有内容都是最新的。如果你遇到问题，请在继续之前解决它们（参见本文档其他条目获取建议，如果未涵盖且你无法解决，请在论坛发帖）。
2. **阅读当前作业的 `grade.txt`**：在你刚完成的作业目录中运行 `cat grade.txt`。它说你得了多少分？如果你没有通过，那么系统还不会发布下一个作业。试着理解并修正你在这个作业中的错误。
3. `cd ~/learn2prog` 然后 `ls`：你现在看到下一个作业了吗？如果看到了，很好。
4. 如果没有，那么你遇到了不寻常的问题，需要在论坛发帖。Drew 会尽快设法解决。

## Nothing to commit, working directory is clean
## 没有要提交的内容，工作目录是干净的

这个错误发生在你尝试执行 `git commit`，但所有内容都与你上一次提交相同。也就是说，自上次提交以来你没有更改任何东西，所以不需要再次提交。你应该确保你已经保存了所有内容。否则，你可以直接 `git push`（如果还没推送）然后 `grade`。

## No changes added to commit
## 没有更改被添加到提交

这个错误发生在有更改，但你没有**暂存**它们以进行提交。也就是说，你更改了文件，但没有执行 `git add` 告诉 git 你想把这些更改放入提交。你可以使用 `git add` 暂存任何你想要的文件（告诉 git 把它们放入下一次提交），或者给 `git commit` 加上 `-a` 选项来提交所有更改的文件：

```bash
git commit -am "Did assignment 46"
```

## 无法 git push：需要先 git pull

（图）

这只是意味着，在 git 拥有评分器所做所有事情的最新副本之前，它无法推送更改。如果你运行 `git pull`，git 会为你打开 `emacs` 来编辑提交消息（它在合并更改时会做一个提交），看起来像这样：

（图）

你可以直接保存（`control-x control-s`）并退出（`control-x control-c`）以接受默认消息。在几乎所有情况下，你会看到类似这样的输出：

（图）

如果发生了上述情况，git 已经自己把两个版本合并在一起。如果这就是发生的情况，你可以 `git push` 和 `grade`。

另一种结果，只有在**你和评分器都修改了相同文件**时才会发生（这不应该发生——不要编辑你的 `grade.txt` 文件！），是 git 无法合并，需要你自己合并。由于这应该极为罕见，我们在末尾的“合并冲突”一节中处理它。

## The below problems should be much rarer (but are listed, as learners have encountered them)
## 以下问题应该罕见得多（但列出是因为学习者遇到过）

### Unable to create '/home/student/learn2prog/.git/index.lock': File exists.
### 无法创建 '/home/student/learn2prog/.git/index.lock'：文件已存在。

这个错误发生在你要么已经有一个 `git` 在运行（可能被挂起），要么 git 以某种方式崩溃了。这个错误真的不应该发生，但最可能的情况是 git 为提交消息打开了 `emacs`，而你把 `emacs` 挂起了（让 git 继续运行，等待提交消息）。

首先运行 `jobs` 查看你挂起了哪些程序。如果你挂起了 git，那么用 `fg` 把它带回前台并完成它。

（图）

否则，只需执行：

```bash
rm /home/student/learn2prog/.git/index.lock
```

然后重试你正在做的 git 命令。

### Git status is not clean, with seemingly no information
### Git 状态不干净，且似乎没有信息

如果你运行 `grade` 并收到关于 git 状态不干净的错误消息，但似乎没有其他信息，仔细看第二行，它应该写着 `Your branch is up-to-date with 'origin/master'`。如果它说了别的，像这样：

（图）

那么你更改了你的**上游远程**（git 认为默认推送/拉取的位置）。评分器对此不高兴，因为你不再默认推送到/拉取它。我们意识到这个错误消息可以更好，但甚至从未想过这个问题会出现。你应该做的第一件事是用命令 `git remote show -v` 检查你名为 `origin` 的远程设置是否正确：

（图）

这里，你要看那两行写着 `origin` 的，并想确保它们写着 `/git-remote/learn2prog`（一行是 `fetch`，另一行是 `push`）。拥有任何其他你想要的远程是可以的（比如你的 github 账号等），只需确保 `origin` 如上设置。

现在运行：

```bash
git push --set-upstream origin master
```

这个命令把你的“上游”（默认推送/拉取远程）设置回评分器。

### 合并冲突

这个问题真的不应该发生：它需要你和评分器修改同一个文件。如果发生了，会是这样：

（图）

这里，git 显示了文件两个不同版本中的内容（评分器的和你的），用 `<<<<`、`====` 和 `>>>>` 标记。`<<<<` 和 `====` 之间的文本是你的版本中的内容，`====` 和 `>>>>` 之间的文本是评分器版本中的内容。把文件编辑成它应该有的样子，保存并退出。然后执行 `git add grade.txt`（或出问题的那个文件），以及 `git commit -m "Fixed merge conflict"`。

## Question: I 'git rm'ed a file, how can I recover?
## 问题：我 `git rm` 了一个文件，如何恢复？

如果你 `git rm` 了一个文件（在这个例子中是 `README`），你不能直接 `git checkout`。相反，你应该先执行：

```bash
git status
```

看看你是否提交了那个删除。

（图）

如果输出像上图，你已经**暂存**但**未提交**删除。正如那里的消息所说，你可以用以下命令撤销：

```bash
git reset HEAD README
git checkout -- README
```

如果你已经提交了删除（在 `git status` 中不像上面那样显示），那么执行：

```bash
git log -- README
git log --name-status -- README
```

你应该会看到类似这样的内容：

（图）

在每个提交的末尾，它列出了更改了什么（这就是 `--name-status` 的作用），`D` 表示删除。找到有 `D` 的那个，然后看它**之前**的那个（在它下面），在这个例子中是 `fd038f06ebe845f65550507d25f1468f3d76ed57`。

所以你需要执行：

```bash
git checkout fd038f06ebe845f65550507d25f1468f3d76ed57 README
```

然后你会想执行 `git add README` 把它放回 git。
