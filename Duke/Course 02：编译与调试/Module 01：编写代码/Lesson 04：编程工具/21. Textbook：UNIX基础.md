# UNIX Basics
# UNIX 基础

UNIX 是一个**多任务、多用户操作系统**，非常适合编程和与编程相关的任务（运行服务器等）。严格来说，UNIX 指的是 20 世纪 70 年代在贝尔实验室开发的一个特定操作系统。然而，如今它更常被（略微不准确地）用来指代“**任何类 UNIX**”操作系统，例如 Linux、FreeBSD、Solaris、AIX，甚至 Mac OSX。在这里，我们将使用更通用的术语，并注意你最可能使用的是 Linux 或 Mac OSX。

UNIX 是**面向专家的工具与面向新手的工具之间权衡**的一个很好的例子，这在本课程前面讨论过。如果你正在阅读这一节，那么你很可能属于相当大的一类人：在使用计算机方面是“**高级新手**”——也就是说，你已经掌握了新手系统的所有技能。你可以使用图形界面打开文件、发送电子邮件、浏览网页和播放音乐。也许当出现问题时，你甚至能修好一些东西。然而，如果要让你的计算机以自动化方式执行中等复杂度的任务，你会感到非常困难。

举个简单的例子，假设一个目录（也就是“文件夹”）中有 50 个文件，你想通过把文件名中的 `_` 替换为 `-` 来重命名它们（其他部分保持不变）。作为“高级新手”，你可以在图形界面中手工完成这个任务——点击每个文件，点击重命名，然后输入新名称。然而，这种方法会极其繁琐且耗时。专家用户会使用**命令行**（我们稍后将介绍）用一条命令重命名所有 50 个文件，只需几秒钟。

## In the Beginning Was the Command Line
## 起初是命令行

虽然 UNIX 有图形界面（GUI），但它的用户经常使用**命令行**。最简单的用法是，命令行让你输入想要运行的程序名称，而基于 GUI 的操作系统可能会让你双击想要运行的程序图标。命令行界面一开始可能令人生畏或令人沮丧，但专家用户通常更喜欢命令行而不是 GUI。除了是编程的自然环境之外，它还允许我们执行更复杂的任务，尤其是自动化那些本来可能重复的任务。

要进入命令行提示符，你需要使用**终端模拟器**（通常简称为“终端”），它是一个模拟文本模式终端的程序。在本课程中，你可以在**实践编程环境**中完成所有需要做的事情。然而，如果你有需要，也可以在自己的机器上访问终端。如果你运行的是基于 UNIX 的系统（Linux 或 Mac OSX），终端是原生可用的。在 Linux 中，如果你使用图形环境，可以运行 `xterm`，或者按 `Ctrl-Alt-F1` 切换到实际的文本模式终端（要切换回图形界面，可以按 `Ctrl-Alt-F7`）。如果你运行的是 Mac OSX，可以运行 `Terminal` 应用程序（通常位于 `Applications > Utilities` 下）。

如果你运行的是 Windows，也有一些命令行选项（通常称为 `cmd` 或 `command`，具体取决于 Windows 版本），然而，按照 UNIX 标准，这些往往相当简陋。事实上，Windows 命令提示符的行为完全不同，并且使用与 Unix shell 不同的命令。如果你愿意，可以安装一个名为 `Cygwin` 的工具，它提供了 UNIX 环境的基础。然而，如果你可以访问 UNIX 服务器（例如，如果你正在上课，老师已经设置了一台供你使用的服务器），通常更容易的做法是远程登录到服务器并在那里工作。

一旦你启动了终端，它应该会显示一个**命令提示符**（简称“提示符”）。提示符不仅让你知道 shell 已准备好接受命令，还提供了一些信息。在本课程中，它不显示用户或主机信息，但在你的机器上会显示。接下来是**当前目录**。在这个例子中，当前目录是 `~/learn2prog/01apple`。`~` 是 UNIX 中“你的主目录”的简写（我们稍后会详细说明）。然后 `learn2prog` 目录位于 `~` 内部，而 `01_apple` 目录又位于其中。之后，`$` 是典型用户提示符结束的典型符号，表示可以输入命令。白色方框是光标，表示你正在哪里输入。

提示符显示这些信息，因为通常立即知道这些信息很有用，而无需运行命令来查明。虽然记住你是谁或你在哪台计算机上看起来微不足道，但跨多台计算机工作是很常见的。例如，开发人员可能在自己的本地计算机上打开一个终端，一个登录到开发团队共享的服务器，第三个登录到用于实验和测试的系统。同样，一个人可能在同一系统上有多个用户名用于不同目的。提示符究竟显示什么信息是可配置的，我们稍后会简要讨论。

## Command line arguments
## 命令行参数

许多 UNIX 命令接受命令行上的**参数**，以指定它们应该做什么。一般来说，命令行参数与命令名（以及彼此之间）用**空白字符**（一个或多个空格或制表符）分隔。例如，`ls -a ..` 将显示父目录中的“所有”文件，包括那些通常不显示的文件。

`..` 是一个参数，告诉 `ls` 显示哪个目录的内容。参数 `-a` 是“**选项**”的一个例子。选项是与“普通”参数不同的参数，它们以连字符 `-` 开头，并改变命令的行为，而不是指定程序的典型细节。

## Directories
## 目录

关于提示符的讨论引入了三个重要概念：**目录**、**当前目录**和**用户的主目录**。目录是文件系统上的组织单位，包含文件和/或其他目录。你可能熟悉“文件夹”这个概念，它是目录的图形化比喻。实际的技术术语，也就是指代文件系统上组织单位的正确方式，是“**目录**”。文件夹实际上只适用于指代许多图形界面中使用的图标。

要理解“当前目录”的重要性，我们必须首先理解**路径名**的概念——我们如何指定特定的文件或目录。在 UNIX 中，文件系统以**层次结构**组织，从**根**开始，根称为 `/`。在根目录内部，有其他目录和文件。这些目录本身可能包含更多目录和文件，依此类推。每个文件（或目录——目录实际上是一种特殊类型的文件）都可以用一个**路径**来命名。路径是在系统中定位文件的方式。**绝对路径名**指定了从根开始必须经过的所有目录。路径名的组成部分用 `/` 分隔。例如，`/home/drew/myfile.txt` 是一个绝对路径名，它指定了 `drew` 目录内的 `myfile.txt`，而 `drew` 目录本身位于 `home` 目录内，`home` 目录又位于文件系统的根目录内。

程序的“**当前目录**”（也称为“**当前工作目录**”或“**工作目录**”）是**相对路径名**的起始目录。相对路径名是不以 `/` 开头的路径名（以 `/` 开头的路径名是绝对路径名）。实际上，相对路径名是通过在其前面加上当前目录的路径而转换为绝对路径名的。也就是说，如果当前工作目录是 `/home/drew`，那么相对路径名 `textbook/chapter4.tex` 指的是 `/home/drew/textbook/chapter4.tex`。

所有程序都有一个当前目录，包括命令 shell。当你第一次启动命令 shell 时，它的当前目录是你的**主目录**。你可以在上面的图片中看到这一点，第一行的提示符是 `[~]`。在 UNIX 系统上，每个用户都有一个主目录，用于存储他们的文件。通常，用户主目录的名称与他们的用户名匹配。在 Linux 系统上，它们通常位于 `/home` 中（因此名为 `drew` 的用户的主目录是 `/home/drew`）。Mac OSX 通常将主目录放在 `/Users` 中（因此 `drew` 会有 `/Users/drew`）。主目录足够重要，以至于它有自己的缩写 `~`。单独使用 `~` 指的是你自己的主目录。`~` 后面紧跟用户名指的是该用户的主目录（例如，`~fred` 会指代 fred 的主目录）。

你应该知道一些有用的与目录相关的命令。第一个是 `cd`，代表“**change directory**”（改变目录）。这个命令将当前目录更改为你作为命令行参数指定的不同目录（回想一下，命令行参数写在命令名之后，并用空白字符与命令名分隔）。例如，`cd /` 会将当前目录更改为 `/`（文件系统的根）。注意，如果没有空格（`cd/`），命令 shell 会将其解释为名为“cd/”的命令，且没有参数，并给出找不到该命令的错误消息。在上面的图片中，你可以看到 `cd` 命令的两次使用。第一次将当前目录从主目录更改为 `learn2prog` 目录。第二次更改为 `00_hello` 目录（它位于 `learn2prog` 目录内部）。

`cd` 的参数可以是你有权限访问的任何目录的路径名（相对或绝对——作为一般规则，你可以使用任何一种）。我们稍后将更详细地讨论权限，但现在只需说，如果你没有权限访问你请求的目录，`cd` 会给出错误消息，并且不会更改目录。

另一个有用的命令是 `ls`，它列出目录的内容——里面有哪些文件和目录。没有参数时，`ls` 列出当前目录的内容。如果你指定一个或多个路径名作为参数，`ls` 将列出关于它们的信息。对于指定目录的路径名，`ls` 将显示目录的内容。对于指定常规文件的路径名，`ls` 将列出所命名文件的信息。你可以在上面的图片中看到两个 `ls` 示例。第一个显示了 `learn2prog` 目录的内容（这里，是本专项课程中课程 2 和 3 的所有作业）。第二个显示了 `00_hello` 目录的内容：一个包含作业说明的 `README`，`hello.txt` 是本作业的交付物，以及 `grade.txt` 给出了对你工作的反馈。

之前的视频展示了使用 `cd` 和 `ls` 命令的示例。示例中的第一个命令是 `cd learn2prog`，它将当前目录更改为相对路径 `examples`。然后提示符显示当前目录为 `~/learn2prog`。第二个命令是 `ls`，它列出 `examples` 目录的内容（因为没有参数，`ls` 列出当前目录的内容）。在这个例子中，当前目录有一个目录（`00_hello`）和一个常规文件（`README`）。大多数系统的默认设置是 `ls` 对其输出进行颜色编码：目录显示为深蓝色，而常规文件显示为纯白色。还有其他文件类型，也会以不同颜色显示。

`ls` 命令还可以接受称为“**选项**”的特殊参数。例如，对于 `ls`，`-l` 选项请求 `ls` 打印它列出的每个文件的额外信息。`-a` 选项请求 `ls` 列出所有文件。相比之下，它的默认行为是跳过名称以 `.`（即点）开头的文件。虽然这种行为看起来奇怪，但它源于 UNIX 约定：当且仅当你通常不想看到它们时，文件才以 `.` 命名。这些“**点文件**”的一个常见用途是配置文件（或目录）。例如，命令 shell（解析并执行你在提示符下输入的命令）在每个用户的主目录中维护一个配置文件。对于命令 shell `bash`，这个文件称为 `.bashrc`。对于命令 shell `tsch`，这个文件称为 `.cshrc`。

其他名称以 `.` 开头的常见文件是特殊目录名 `.` 和 `..`。在任何目录中，`.` 指的是该目录本身（因此 `cd .` 什么也不做——它会切换到你已经在的目录）。当你需要显式指定当前目录中的某些内容时（`./myCommand`），这个名称很有用。名称 `..` 指的是当前目录的**父目录**——也就是说，这个目录所在的目录。使用 `cd ..` 会在目录层次结构中带你“向上一级”。例外情况是根目录中的 `..`，它指回根目录本身，因为你不能再“向上”了。

`ls` 命令有许多其他选项，许多 UNIX 命令也是如此。随着时间的推移，你会熟悉你经常使用的选项。然而，你可能想知道如何了解你不知道的其他选项。像大多数 UNIX 命令一样，`ls` 有一个 **man 页面**（如我们之前讨论的），它描述了如何使用该命令以及它接受的各种选项。你可以在命令提示符下输入 `man ls` 来阅读这个手册页。

另外两个有用的与目录相关的命令是 `mkdir` 和 `rmdir`。`mkdir` 命令接受一个参数，并创建指定名称的目录。`rmdir` 命令接受一个参数，并删除指定的目录。要使用 `rmdir` 删除目录，该目录必须是空的（它必须不包含任何文件或目录，除了 `.` 和 `..`，它们不能被删除）。
