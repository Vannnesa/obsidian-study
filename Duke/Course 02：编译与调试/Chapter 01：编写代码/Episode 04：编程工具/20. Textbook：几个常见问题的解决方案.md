# Solutions to a Few Common Problems
# 几个常见问题的解决方案

虽然你现在可能不需要这些信息，但我们想在你可能在**实践编程环境**（Practice Programming Environment，PPE）中遇到这些常见问题之前，先把它们提供给你。如果你遇到了，记住你可以回到这篇阅读材料来寻求帮助。

## Common Problem 1: “git status is not clean” when trying to “grade”
## 常见问题 1：尝试“grade”时出现“git status is not clean”

如果你有文件**没有放入 git**，那么当你评分时，你会遇到类似这样的错误消息：

![[Pasted image 20260918074254.png]]

`grade` 命令要求**所有文件**要么**放入 git 并推送**，要么**显式忽略**。它这样做是为了避免你因为只有部分工作被评分而困惑（评分器只会看到放入 git 并推送的文件）。

那么如何修复这个错误？要么把错误消息中列出的文件加入 git，然后 `git push`（如果你想保留它们），要么删除这些文件（如果你不想保留）。如果不确定，那就先把文件加进去。如果你想添加文件，对于相关文件名使用 `git add`：

```bash
$ git add filename1 filename2  ...
```

（上面的 `$` 字符是你的终端提示符。你不需要输入它。）在上面的例子中，我们会执行：

```bash
$ git add anotherfile
```

然后使用 `git commit` 提交文件。然后执行 `git push`。现在你可以执行 `grade` 了。

如果你想删除文件，使用 `rm filename` 删除文件。

## Common Problem 2: “git push” gives you a “[rejected]” message
## 常见问题 2：“git push”给出“[rejected]”消息

如果你在存在**你没有的更改**时尝试执行 `git push`，你会得到类似这样的消息：

![[Pasted image 20260918074303.png]]

这通常发生在你运行了 `grade`（它会把评分报告放入你的远程仓库），但还没有执行 `git pull` 来接收该评分报告时。这个问题的解决办法就是运行：

```bash
$ git pull
```

这会拉取远程更改。之后，你应该能够再次运行 `git push`。

## Common Problem 3: how do I delete files like  hello.txt? Why are they created?
## 常见问题 3：如何删除像 `#hello.txt#` 这样的文件？它们为什么被创建？

这些文件是 `Emacs` 在你**未能正确退出 Emacs** 时创建的。如果你看到这些文件出现，你可以按 **Tab 自动补全**，或者使用**转义字符**（`\#`）删除这些文件。见下面示例。

```bash
$ rm \#hello.txt#
```

## Common Problem 4: I didn't change files, but git is showing them as modified
## 常见问题 4：我没有更改文件，但 git 显示它们已被修改

当打开一个作业时，你可能会注意到 `git status` 显示你之前作业的许多文件**已被修改**，即使你没有编辑它们。这是因为当你一段时间不使用 PPE 时，Coursera 会将其关闭，下次你访问时它会再次启动环境。作为这个启动过程的一部分，它会将你主文件夹中所有文件的 **Unix 权限**修改为所有用户可读-写-执行（`rwx`）。你通过 `Emacs` 和本课程中其他程序创建的文件通常被创建为**你可读-写，其他用户只读**。Git 会跟踪权限更改，因此当文件的权限被更改时，会显示这些文件已被修改。如问题 1 所述，这种“**不干净**”状态会阻止你运行 `grade`。

那么如何修复？把这些权限更改加入 git 没有坏处（而且每个文件应该只需要一次）：

```bash
$ cd ~/learn2prog
$ git status  <== (确保你想把这些文件/更改都加入 git)
$ git add .
$ git commit -m "Permission changes"
```
